# 07-1 解答

[07-1 プロンプトの設計](../07-1-prompt-design.md) の演習の解答の一例です。

## 1・2 例示を 1 件足す

`PromptSpec` は frozen（変更できない）なので、`dataclasses.replace` で、例示だけを差し替えた写しを作ります。

```python
from dataclasses import replace

from roadmap_examples.p07_prompt import DEFAULT_SPEC, Example, build_messages

SPEC_WITH_PLAN_EXAMPLE = replace(
    DEFAULT_SPEC,
    examples=DEFAULT_SPEC.examples
    + (Example("毎月の料金が高いので、安いプランにしたいです。", "contract", "料金ではなくプランの変更の依頼"),),
)


def test_spec_with_plan_example_has_ten_messages() -> None:
    messages = build_messages(SPEC_WITH_PLAN_EXAMPLE, "請求書がほしい")
    assert len(messages) == 10
    assert [m.role for m in messages[-3:]] == ["user", "assistant", "user"]
    assert "安いプラン" in messages[-3].content
```

なぜこうするか:

- 元の `DEFAULT_SPEC` を書き換えないので、元のプロンプトと、例示を足したプロンプトを並べて比べられます
- 足した例は「料金」という語があっても contract を選ぶ見本です。理由（reason）に判断の基準を書くと、モデルがそれをまねます
- テストは件数だけでなく、最後の例示が足した例であることも確かめます（並び順の誤りに気づける）

別の書き方でもよい点: テストの置き場所（`examples/tests/` の新しいファイル）と名前は自由です。`uv run pytest` が通れば構いません。

## 3 例示ありとなしで比べる（任意）

```python
from dataclasses import replace

from roadmap_examples.ollama_client import OllamaChat
from roadmap_examples.p07_prompt import DEFAULT_SPEC, build_messages

llm = OllamaChat("<モデル名>", options={"temperature": 0})
no_examples = replace(DEFAULT_SPEC, examples=())
inquiries = {
    "c005": "解約したはずの月の分まで引き落とされています。",
    "c023": "支払いの負担が大きいので、安いプランを検討しています。",
}
for case_id, text in inquiries.items():
    for name, spec in (("例示あり", DEFAULT_SPEC), ("例示なし", no_examples)):
        answers = [llm.complete(build_messages(spec, text)).text for _ in range(3)]
        print(case_id, name, answers)
```

結果は、次のような表にまとめます（答えはモデルと手元の環境で変わるので、ここでは形だけを示します）。

| 件 | 正解 | 例示あり（3 回） | 例示なし（3 回） |
|---|---|---|---|
| c005 | billing | （3 回の答え） | （3 回の答え） |
| c023 | contract | （3 回の答え） | （3 回の答え） |

考察で見るところ:

- 例示なしで「解約」「支払い」という語に引きずられた答えが増えたか。増えたなら、例示の reason が判断の基準を伝えていたことになります
- `temperature` が 0 でも、3 回の答えがそろわないことがあります。1 回の結果で良し悪しを決めず、07-5 の評価セットで件数を増やして比べます
- JSON ではなく文章で答えた回があったか。あれば、07-2 の構造化出力で防ぎます
