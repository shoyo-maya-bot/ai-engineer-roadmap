# 07-4 解答

[07-4 費用の最適化](../07-4-cost.md) の演習の解答の一例です。

## 1 重ねる順番

2 通りの順番で、どちらも求める動きになることを確かめます。

- 順番 A: `CachedLLM(BudgetedLLM(LimitedLLM(本物)))`（キャッシュがいちばん外）
- 順番 B: `BudgetedLLM(CachedLLM(LimitedLLM(本物)))`（費用の上限がいちばん外）

```python
import pytest

from roadmap_examples.llm import FakeLLM, LimitedLLM, Message
from roadmap_examples.p07_cost import BudgetedLLM, CachedLLM, Price

PRICE = Price(100.0, 400.0)  # テスト用の架空の単価
SAME = [Message("user", "請求書を再発行して")]


def order_a(fake: FakeLLM) -> tuple[CachedLLM, BudgetedLLM]:
    budget = BudgetedLLM(LimitedLLM(fake, max_calls=10, max_tokens=10_000), PRICE, max_cost=1.0)
    return CachedLLM(budget), budget


def order_b(fake: FakeLLM) -> tuple[BudgetedLLM, BudgetedLLM]:
    budget = BudgetedLLM(CachedLLM(LimitedLLM(fake, max_calls=10, max_tokens=10_000)), PRICE, max_cost=1.0)
    return budget, budget


@pytest.mark.parametrize("build", [order_a, order_b])
def test_second_call_is_cached_and_free(build) -> None:
    fake = FakeLLM.of(["billing"])
    llm, budget = build(fake)
    llm.complete(SAME)
    spent = budget.spent
    llm.complete(SAME)
    assert len(fake.calls) == 1  # 2 回目は内側の LLM を呼ばない
    assert budget.spent == spent  # キャッシュから返した分は、費用に数えない
```

どちらも、求める 2 つの動きになります（B では、キャッシュがトークン数 0 の `Completion` を返すので、費用が増えません）。
違いは、費用の上限に達した後です。

| 順番 | 上限に達した後に、同じメッセージが来たら |
|---|---|
| A（キャッシュが外） | キャッシュから返す（お金はかからないので、止める理由がない） |
| B（上限が外） | キャッシュにあっても止める |

お金のかからない応答まで止める理由はないので、A をおすすめします。
一方、`LimitedLLM` をキャッシュの外に置くと、キャッシュから返した分も呼び出しの回数に数えてしまいます。
上限（回数・トークン・費用）は、本物を呼ぶ直前に置きます。

別の書き方でもよい点: 「上限に達した後でも、キャッシュにある分は返せる」ことを確かめるテストを足すと、A と B の違いをテストで示せます。

## 2 鍵にモデル名を含める

`CachedLLM` のコードを変えずに、モデルごとに別の入れ物（`store`）を渡す方法があります。

```python
from roadmap_examples.ollama_client import OllamaChat
from roadmap_examples.p07_cost import CachedLLM

stores: dict[str, dict[str, str]] = {}


def cached(model: str) -> CachedLLM:
    return CachedLLM(OllamaChat(model, options={"temperature": 0}), store=stores.setdefault(model, {}))
```

モデル名ごとに入れ物が分かれるので、モデルを替えると、前のモデルの答えは返りません。
`temperature` などの設定も変えるなら、`setdefault` の鍵を `f"{model}:{temperature}"` のように設定ごとにします。
`cache_key` に、モデル名を足す形に書き換えてもかまいません（その場合は、テストも足します）。

## 3 月 1 万件のトークン数を見積もる（任意）

```python
from roadmap_examples.evalset import exact_match, load_cases, run_eval
from roadmap_examples.ollama_client import OllamaChat
from roadmap_examples.p07_classify import DEFAULT_EVAL, llm_predict
from roadmap_examples.p07_structured import CLASSIFY_SCHEMA

cases = load_cases(DEFAULT_EVAL)
llm = OllamaChat("<モデル名>", format=CLASSIFY_SCHEMA, options={"temperature": 0})
report = run_eval(cases, llm_predict(llm), exact_match("category"))
per_case_in = report.input_tokens / len(cases)
per_case_out = report.output_tokens / len(cases)
print(f"1 件あたり: 入力 {per_case_in:.0f} / 出力 {per_case_out:.0f}")
print(f"月 1 万件: 入力 {per_case_in * 10_000:,.0f} / 出力 {per_case_out * 10_000:,.0f}")
```

見積もりの式: 月のトークン数 = 1 件あたりのトークン数 × 月の件数。費用にするには、使う API の公式の料金ページの単価を掛けます。

記録すること: モデル名・件数（30 件）・頼み直しの回数（`ask_json` が頼み直した分もトークン数に入る）。
クラウドの API ではトークンの数え方が違うので、この数字は目安です。
