# 06-4 解答

[06-4 モデルの選び方](../06-4-choosing-models.md) の演習の解答の一例です。

## 1 動かせるモデルの大きさを見積もる

```python
from roadmap_examples.p06_compare import weights_gb

BITS = 4.9  # Q4_K_M のおおよそのビット数（llama-quantize の説明の表）
MARGIN = 1.5  # 重みの 1.5 倍を、必要なメモリとみなす（コンテキストと実行の分）


def max_params_billion(memory_gb: float, bits: float = BITS, margin: float = MARGIN) -> float:
    """memory_gb に入るパラメータの数（10 億単位）の目安."""
    return memory_gb / margin / weights_gb(1, bits)


def test_max_params_billion() -> None:
    # 例: 16 GB のメモリなら、16 / 1.5 / 0.6125 ≒ 17.4B まで
    assert round(max_params_billion(16), 1) == 17.4
```

なぜこうするか:

- 余裕の倍率（`MARGIN`）を名前のある定数にしておくと、見積もりの前提が読み手に伝わります
- ほかのアプリもメモリを使います。PC のメモリ全部を使える前提にせず、さらに余裕を見ておきます（例: 16 GB の PC なら 10 GB を上限にする）
- 見積もりは目安です。最後は、実際に動かして `ollama ps` と、06 の表の秒数で確かめます

## 2 出力の速さの列を足す

`to_markdown` の「モデルごと」の表を、次のように直します（変えるところだけ）。

```python
def summary_row(model: str, mine: list, details: dict) -> str:
    seconds = sum(r.seconds for r in mine)
    speed = sum(r.output_tokens for r in mine) / seconds if seconds else 0.0
    d = details.get(model, {})
    return f"| {model} | {d.get('parameter_size', '')} | ... | {seconds:.1f} | {speed:.1f} |"
```

テストは、決まった秒数の行を渡して、列の値を確かめます。

```python
from roadmap_examples.p06_compare import Row


def test_speed_column() -> None:
    rows = [Row("m1", "q1", "東京", 20, 30, 2.0, 1.0), Row("m1", "q2", "2", 10, 10, 2.0, 1.0)]
    line = summary_row("m1", rows, {})
    assert line.endswith("| 4.0 | 10.0 |")  # 出力 40 トークン ÷ 4.0 秒
```

なぜこうするか:

- 1 行を作る部分を関数に分けると、表全体を組み立てなくても、1 行だけでテストできます
- 秒の合計が 0 のとき（テストで時計を止めた場合など）に 0 で割らないようにしています
- 速さは「出力トークン ÷ 秒」にしています。秒には入力を読む時間も入るので、入力が長い質問では速さが低く出ます。
  より正確には、Ollama の応答の `eval_count` と `eval_duration`（出力を作った時間）から計算できます
  （[公式ドキュメント: チャットの API](https://docs.ollama.com/api/chat)）

## 3 表を作ってモデルを選ぶ（任意・成果物）

```bash
uv run python -m roadmap_examples.p06_compare --model <モデル名 1> --model <モデル名 2> --out compare.md
uv run python -m roadmap_examples.p06_compare --model <モデル名 1> --model <モデル名 2> --out compare.md  # 2 回目（読み込みの時間を除く）
```

表の形は本文のとおりです（数字はモデルと PC で変わるので、ここでは示しません）。条件として、次を表の下に書き添えます。

- PC（CPU・メモリ・GPU の有無）と、`ollama ps` の Processor の表示
- 使ったモデル名と、`--num-predict`・`--max-tokens`

選んだ理由の書き方の例:

- 「語の平均は 2 つとも同じだった。小さいほうが秒の合計が半分ほどだったので、小さいほうを使う。`capabilities` に `tools` がある」
- 「小さいほうは q03 の計算を誤り、q07 で架空の売上を答えた。大きいほうは遅いが、メモリに収まり、07 の分類の精度を優先して大きいほうを使う」

どちらの判断も、07-5 の評価セットで精度を測り直して確かめます。06 の 8 問は、選ぶための最初の目安です。
