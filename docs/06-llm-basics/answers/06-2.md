# 06-2 解答

[06-2 LLM の仕組みとコンテキストウィンドウ](../06-2-context-window.md) の演習の解答の一例です。

## 1 rough_tokens で数えて削る

```python
from roadmap_examples.llm import Message, rough_tokens
from roadmap_examples.p06_context import fit_history

HISTORY = [
    Message("system", "あなたは備品の貸出の係です。" * 2),
    Message("user", "a" * 400),  # 約 100 トークン
    Message("assistant", "b" * 200),  # 約 50
    Message("user", "c" * 400),
    Message("assistant", "d" * 200),
    Message("user", "e" * 400),
    Message("assistant", "f" * 80),  # 約 20
]


def test_fewer_messages_survive_as_context_shrinks() -> None:
    counts = [
        len(fit_history(HISTORY, max_context=size, reserve_output=100, count=rough_tokens))
        for size in (2000, 500, 300, 200)
    ]
    assert counts == sorted(counts, reverse=True)  # 上限を小さくするほど、残る件数は減る（増えない）
    assert counts[0] == len(HISTORY)
    assert all(fit_history(HISTORY, size, 100)[0].role == "system" for size in (2000, 500, 300, 200))
```

なぜこうするか:

- 件数そのものではなく「上限を小さくすると減る（増えない）」という性質を確かめています。数え方を替えても、この性質は変わらないはずだからです
- system がいつも先頭に残ることも、同じテストで確かめます
- `rough_tokens` は `len(text) // 4` なので、`"a" * 400` は 100 トークンと数えます。本物のトークン数とは違うので、テストの数字を本物の見積もりに使ってはいけません

## 2 temperature と選ばれる回数

```python
import random

from roadmap_examples.p06_context import sample, softmax


def count_top(temperature: float, n: int = 1000) -> int:
    rng = random.Random(0)
    probs = softmax([2.0, 1.0, 0.1], temperature)
    return sum(1 for _ in range(n) if sample(probs, rng) == 0)


def test_lower_temperature_picks_the_top_more_often() -> None:
    low, mid, high = count_top(0.5), count_top(1.0), count_top(2.0)
    assert low > mid > high
    assert count_top(0) == 1000
```

なぜこうするか:

- 乱数の種（`random.Random(0)`）を固定すると、何度流しても同じ回数になり、テストが毎回同じ結果になります
- 回数のぴったりの値ではなく、大小の関係を確かめています。乱数の作り方が Python の版で変わっても、テストが壊れにくくなります
- temperature 0 では、いつもいちばん点数の高いものが選ばれます（1,000 回とも）

## 3 num_ctx を小さくする（任意）

```python
from pathlib import Path

from roadmap_examples.llm import Message
from roadmap_examples.ollama_client import OllamaChat

text = Path("data/p08/docs/02-api.md").read_text(encoding="utf-8")  # examples/ で実行する
question = Message("user", f"次の設計書を、最後の節まで含めて 3 行で要約してください。\n\n{text}")
for num_ctx in (512, 8192):
    llm = OllamaChat("<モデル名>", options={"temperature": 0, "num_ctx": num_ctx})
    result = llm.complete([question])
    print(num_ctx, result.input_tokens, result.text)
```

メモは次の形にまとめます（数字と答えはモデルと環境で変わるので、ここでは形だけを示します）。

| num_ctx | 入力トークン | 最後の節に触れたか | 気づいたこと |
|---:|---:|---|---|
| 512 | （表示された値） | （はい・いいえ） | |
| 8192 | （表示された値） | （はい・いいえ） | |

考察で見ること:

- `num_ctx` が小さいとき、入力トークンが設計書の長さから思うより少なくなっていないか（全部は読まれていない、のサイン）
- 答えが、設計書の前半だけを要約していないか
- どちらの場合もエラーにならないなら、「上限を超えても気づけない」ことになります。コードの側で入力のトークン数を記録しておく理由です
