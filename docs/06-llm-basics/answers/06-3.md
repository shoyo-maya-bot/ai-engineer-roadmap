# 06-3 解答

[06-3 事前学習・指示調整・ファインチューニングの違い](../06-3-training-stages.md) の演習の解答の一例です。

## 1 区切りの分のトークン数

```python
from roadmap_examples.llm import Message
from roadmap_examples.p06_template import overhead_tokens

PARTS = ["貸出は 14 日まで。", "延長は 1 回。", "延長は 7 日。", "延滞中は借りられない。", "返却は窓口で。"]


def test_more_messages_mean_more_overhead() -> None:
    one = [Message("user", "".join(PARTS))]
    five = [Message("user", p) for p in PARTS]
    assert overhead_tokens(five, len) > overhead_tokens(one, len)
    # 中身は同じ. 違いは区切り（<|user|> と <|end|> など）の数だけ
    assert sum(len(m.content) for m in five) == len(one[0].content)
```

なぜこうするか:

- 中身の合計が同じことも確かめています。違いが区切りの数だけから来ていると言えるようにするためです
- `len` で数えているので、区切りの「文字数」の差です。本物のトークン数の差は、本物のテンプレートとトークナイザーで変わります。
  ただ「メッセージが増えるほど区切りの分が増える」という性質は同じです

## 2 何で直すか

| 要望 | 先に試すこと | 理由 |
|---|---|---|
| 答えをいつも JSON で返してほしい | 構造化出力（07-2） | スキーマを渡して形を制約し、受け取った後にも検証できる。学習は要らない |
| 先週改訂された旅費の規程に答えてほしい | RAG（08） | 改訂のたびに資料を差し替えるだけで済む。どの条文を根拠にしたかも示せる |
| 分類を、小さく安いモデルで同じ精度でしたい | まずプロンプトとモデルの使い分け（07-1・07-4）、足りなければファインチューニング（09） | 決まった仕事を安いモデルで安定させるのは、ファインチューニングが効きやすい場面。ただし評価セット（07-5）で、プロンプトだけで届かないことを先に確かめる |
| 答えの最後に、窓口を書き添えてほしい | コードで足す（またはプロンプト） | 毎回同じ文章なら、モデルに書かせずにコードで末尾に足すのが確実で安い |

なぜこうするか:

- 4 つ目のように、LLM を使わずにコードで済むことは、コードで済ませます。モデルに書かせると、書き忘れや言い換えが起きます
- 3 つ目は、ファインチューニングが向く数少ない場面です。それでも「先にプロンプトで試し、評価セットで足りないと分かってから」という順は変えません

## 3 テンプレートを見る・raw で送る（任意）

```bash
curl http://localhost:11434/api/show -d '{"model": "<モデル名>"}'
```

応答の `template` に、`.System`・`.Prompt`・`.Response` のような変数と、その前後の区切りの文字列が書かれています
（変数の意味は [Modelfile の TEMPLATE](https://docs.ollama.com/modelfile) の表）。
`template_source` が `go_template` 以外のモデルでは、`template` が使われていないことがあります
（[公式ドキュメント: モデルの詳細](https://docs.ollama.com/api-reference/show-model-details) の `template_source` の説明）。

```bash
curl http://localhost:11434/api/generate -d '{"model": "<モデル名>", "prompt": "日本の首都は", "stream": false, "options": {"num_predict": 30}}'
curl http://localhost:11434/api/generate -d '{"model": "<モデル名>", "prompt": "日本の首都は", "raw": true, "stream": false, "options": {"num_predict": 30}}'
```

メモは次の形にまとめます。

| 送り方 | 答え（先頭） | 気づいたこと |
|---|---|---|
| テンプレートあり | （表示された答え） | 例: 「東京です。」のように、質問への答えとして書いた |
| `raw`（テンプレートなし） | （表示された答え） | 例: 「東京で、人口は…」のように、文の続きとして書いた |

どう違うかはモデルによります。違いが出なかった場合も、その結果と、使ったモデル名を書いておきます。
