## 1 「解約の」を 1 つのトークンにする

```python
from roadmap_examples.p06_tokens import tokenize, train_bpe

CORPUS = ["注文の状態", "注文の取り消し", "注文番号", "請求書の再発行", "請求書の宛名"]
MORE = ["解約の手続き", "解約の時期", "解約の理由"]


def test_cancel_becomes_one_token() -> None:
    merges = train_bpe(CORPUS + MORE, num_merges=20)
    assert tokenize("解約の相談", merges)[0] == "解約の"
```

なぜこうするか:

- 「解」と「約」、「約」と「の」の組が 3 回ずつ並ぶので、まとめる候補の上位に入ります
- `num_merges` を大きめ（20）にしています。小さいと、ほかの組（「注文」など）を先にまとめ終えたところで止まり、「解約の」まで届かないことがあります
- 確かめる文章は、学習に使っていない「解約の相談」にしています。学習した文章だけで確かめると、覚えただけかどうかが分かりません

## 2 まとめる回数とトークン数

```python
import pytest

from roadmap_examples.p06_tokens import tokenize, train_bpe

CORPUS = ["注文の状態", "注文の取り消し", "注文番号", "請求書の再発行", "請求書の宛名"]


@pytest.mark.parametrize(
    ("num_merges", "seen", "unseen"),
    [
        (0, 7, 7),  # まとめない: 1 文字 1 トークン
        (5, 5, 7),  # 「注文の」が 1 つになる
        (20, 5, 7),  # 2 回以上並ぶ組を使い切ると、それ以上は減らない
    ],
)
def test_tokens_by_num_merges(num_merges: int, seen: int, unseen: int) -> None:
    merges = train_bpe(CORPUS, num_merges)
    assert len(tokenize("注文の取り消し", merges)) == seen
    assert len(tokenize("配送日の変更願", merges)) == unseen
```

数は、この `CORPUS` で手元で実行して確かめた値です。コーパスを変えると変わります。

なぜこうするか:

- 学習した文章（「注文の取り消し」）は、まとめる回数を増やすとトークンが減ります。学習で見なかった文章（「配送日の変更願」）は、7 文字のまま減りません
- 回数を増やし続けても、2 回以上並ぶ組が無くなると止まります（`train_bpe` の `n < 2`）。本物のトークナイザーは、大量の文章で数万回まとめて語彙を作ります
- `parametrize` で表にしておくと、どの条件で何が変わったかを、テストの一覧として読めます
