## 1・2 SGD・モーメンタム・Adam を比べる

```python
import numpy as np

from roadmap_examples.p05_loop import SGD, Adam, fit, moons
from roadmap_examples.p05_mlp import Params, init_params, predict


class MomentumSGD(SGD):
    """勾配の移動平均（速度）の向きに進む. 谷の底を行き来する動きが打ち消される."""

    def __init__(self, params: Params, lr: float = 0.1, momentum: float = 0.9) -> None:
        super().__init__(params, lr)
        self.momentum = momentum
        self.velocity = {k: np.zeros_like(v) for k, v in params.items()}

    def step(self, grads: Params) -> None:
        for name, p in self.params.items():
            self.velocity[name] = self.momentum * self.velocity[name] + grads[name]
            p -= self.lr * self.velocity[name]


def run(make) -> tuple[int, int, float, float]:
    """（止まったエポック数, 最良のエポック（1 から数える）, 最良の検証の損失, 検証の正解率）."""
    x, y = moons()
    params = init_params(2, 16, 2, seed=0)
    h = fit(params, make(params), (x[:210], y[:210]), (x[210:], y[210:]), epochs=300)
    accuracy = float((predict(h.best_params, x[210:]) == y[210:]).mean())
    return len(h.train_losses), h.best_epoch + 1, min(h.val_losses), accuracy


def test_compare_optimizers() -> None:
    sgd = run(lambda ps: SGD(ps, lr=0.1))
    momentum = run(lambda ps: MomentumSGD(ps, lr=0.1, momentum=0.9))
    adam = run(lambda ps: Adam(ps, lr=0.01))
    assert momentum[1] < adam[1] < sgd[1]  # 最良に届くまでのエポック
    assert min(sgd[3], momentum[3], adam[3]) > 0.9
```

手元の結果:

| 最適化の手法 | 止まったエポック数 | 最良のエポック | 最良の検証の損失 | 検証の正解率 |
|---|---:|---:|---:|---:|
| SGD（学習率 0.1） | 300 | 299 | 0.124 | 95.6% |
| モーメンタム（学習率 0.1・0.9） | 82 | 62 | 0.104 | 95.6% |
| Adam（学習率 0.01） | 169 | 149 | 0.108 | 96.7% |

考察の例:

- SGD は 300 エポックでも最良を更新し続けていて、まだ下がりきっていません
- モーメンタムは、同じ向きの勾配が続くと速度が積み上がり、少ないエポックで低い損失に届きました
- 検証の正解率は 90 点で 1 点が 1.1 ポイントなので、95.6% と 96.7% の差は 1 点です。この差で手法の優劣は言えません
- 学習率はどれも 1 つしか試していません。手法を比べるときは、それぞれの学習率を何通りか試してから比べるのが公平です

なぜこうするか:

- `SGD` を継承して `step` だけを書き換えると、`fit` をそのまま使えます。`fit` は `step(grads)` を呼ぶことしか知らないからです
- 速度の配列は、パラメーターと同じ形で 0 から始めます

## 3 PyTorch の版と比べる（任意）

本文の例を、最後に検証の正解率を出すように足して動かします。

```python
with torch.no_grad():
    accuracy = (model(val_x).argmax(dim=1) == val_y).float().mean().item()
print(best_epoch, epoch + 1, best, accuracy)
```

手元では、最良は 133 エポック目、153 エポック目で止まり（どちらも 1 から数えた値。コードの `best_epoch` と `epoch` は 132 と 152）、最良の検証の損失は 0.102、検証の正解率は 95.6% でした。

考察の例:

- NumPy の版の Adam（最良 149 エポック目・96.7%）と、近い結果になりました。組み立てが同じなので、学習の進み方も似ます
- 一致しないのは、重みの初期値の作り方と、ミニバッチの混ぜ方の乱数が違うためです。同じ種（0）を使っても、乱数の作り方が違えば値は変わります
- PyTorch の版では、勾配の式を 1 行も書いていません。層を替える（`nn.Tanh` を `nn.ReLU` にする）だけで、05-1 の演習 1 と同じことができます
