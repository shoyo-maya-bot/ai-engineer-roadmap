## 1 03 の成果物の問い合わせだけで学習する

```bash
uv run python -m roadmap_examples.p05_charlm --corpus data/p03/inquiries_clean.csv
uv run python -m roadmap_examples.p05_charlm
```

手元の結果（最後の行は 2000 ステップ目）:

| 文章 | 語彙 | 学習・検証の文字数 | 何も学んでいないときの損失 | 学習の損失 | 検証の損失 |
|---|---:|---:|---:|---:|---:|
| 03 の成果物の問い合わせ | 379 | 2,366・267 | 5.94 | 0.43 | 7.94 |
| 部品の組み合わせ | 112 | 33,183・3,713 | 4.72 | 0.32 | 0.33 |

考察の例:

- 03 の成果物の問い合わせでは、学習の損失は下がったのに、検証の損失は 500 ステップ目（6.31）から上がり続け、何も学んでいないときより悪くなりました。丸暗記です
- 文字の種類（379）に比べて文章が短く、検証の行にしか出てこない文字や言い回しが多いためです
- 部品の組み合わせの文章は、言い回しの種類が少なく量が多いので、学習に使っていない行も当てられます。
  ただし、それは「部品の組み合わせ方」を学んだだけで、言葉の意味を学んだわけではありません

## 2 温度を変える

```bash
uv run python -m roadmap_examples.p05_charlm --steps 2000 --save charlm.npz
uv run python -m roadmap_examples.p05_charlm --load charlm.npz --prompt 請求 --length 40 --temperature 0.2 --seed 1
uv run python -m roadmap_examples.p05_charlm --load charlm.npz --prompt 請求 --length 40 --temperature 0.8 --seed 1
uv run python -m roadmap_examples.p05_charlm --load charlm.npz --prompt 請求 --length 40 --temperature 2.0 --seed 1
```

手元の結果:

| 温度 | 作られた文章（改行は「/」） |
|---:|---|
| 0.2 | 請求書の確認方法を教えてください。/ すみません、契約の確認方法を教えてください。/ お |
| 0.8 | 請求書を変更したいです。よろしくお願いします。/ どこから変えられますか。ご確認くださ |
| 2.0 | 請求書人数メールアドレを変更したいです。あります。請求書の使い方が分かりません。よろ |

考察の例:

- 0.2 と 0.8 では、学習した部品どおりの文になりました（0.8 では「どこから変えられますか。」のように、頭の語が抜けた行も出ました）
- 2.0 では「請求書人数メールアドレを」「あります。」のように、学習に無い崩れた並びが出ました。確率の低い文字も選ばれやすくなるためです
- 部品の組み合わせの文章は言い回しが少なく、モデルの確率が 1 つの文字に強く偏るので、温度 1.5 ほどではまだ崩れにくいです（手元で確かめた範囲）
- 温度で割ると、確率の差が、小さい温度では広がり、大きい温度では縮みます。06-2 で LLM の温度を変えたときと同じ仕組みです

## 3 コンテキストの長さを変える

```python
from roadmap_examples.p05_charlm import Config, template_corpus, train


def test_longer_context_predicts_better() -> None:
    text = template_corpus()
    short = train(text, steps=2000, cfg=Config(context=2))
    long = train(text, steps=2000, cfg=Config(context=16))
    assert long.log[-1][2] < short.log[-1][2]
```

手元の結果（2000 ステップ目の検証の損失）:

| context | 2 | 4 | 16 |
|---|---:|---:|---:|
| 検証の損失 | 0.75 | 0.52 | 0.33 |

考察の例:

- 直前の 2 文字しか見えないと、「の」の次に何が来るかを、前の語（「請求書の」か「プランの」か）で区別できません
- 16 文字あれば、文の頭（「お世話になっております。」の後か、など）まで見えて、次の文字を絞り込めます
- テストは 2 回の学習で 10 秒ほどかかります。CI に入れるなら、ステップ数や文章を小さくして数秒に収めます

## 4 PyTorch の版で層の数を変える（任意）

本文の例で、`CharLM(len(vocab.chars), layers=1)` にして動かし、パラメーターの数を数えます。

```python
print(sum(p.numel() for p in model.parameters()))
```

手元の結果:

| layers | パラメーターの数 | 1000 ステップ目の検証の損失 |
|---:|---:|---:|
| 1 | 66,608 | 0.29 |
| 2 | 116,592 | 0.31 |

考察の例:

- 層を 1 つ足すと、パラメーターは約 5 万個増えます（アテンションと全結合の重み）
- この文章では、損失はほとんど変わりませんでした。部品の組み合わせ方が単純で、1 層で学びきれるためです
- 検証の損失は、ランダムに選んだ 1 つのミニバッチで測っているので、0.02 ほどの差はばらつきの範囲です。
  比べるときは、演習のコード（NumPy の版）の `mean_loss` のように、検証の全部で測ります
