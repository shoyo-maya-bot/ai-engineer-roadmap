# 05-4 解答

[05-4 トランスフォーマーを小さく実装する](../05-4-small-transformer.md) の演習の解答の一例です。

## 1 04 の学習データだけで学習する

```bash
uv run python -m roadmap_examples.p05_charlm --corpus data/p04/train.jsonl
uv run python -m roadmap_examples.p05_charlm
```

手元の結果（最後の行は 2000 ステップ目）:

| 文章 | 語彙 | 文章の文字数 | 何も学んでいないときの損失 | 学習の損失 | 検証の損失 |
|---|---:|---:|---:|---:|---:|
| 04 の学習データ | 338 | 2,303 | 5.82 | 0.41 | 8.15 |
| 部品の組み合わせ | 112 | 46,839 | 4.72 | 0.35 | 0.36 |

考察の例:

- 04 の学習データでは、学習の損失は下がったのに、検証の損失は 500 ステップ目（6.25）から上がり続け、何も学んでいないときより悪くなりました。丸暗記です
- 文字の種類（338）に比べて文章が短く、検証の行にしか出てこない文字や言い回しが多いためです
- 部品の組み合わせの文章は、言い回しの種類が少なく量が多いので、学習に使っていない行も当てられます。
  ただし、それは「部品の組み合わせ方」を学んだだけで、言葉の意味を学んだわけではありません

## 2 温度を変える

```bash
uv run python -m roadmap_examples.p05_charlm --steps 2000 --save charlm.npz
uv run python -m roadmap_examples.p05_charlm --load charlm.npz --prompt 請求 --length 40 --temperature 0.2
uv run python -m roadmap_examples.p05_charlm --load charlm.npz --prompt 請求 --length 40 --temperature 0.8
uv run python -m roadmap_examples.p05_charlm --load charlm.npz --prompt 請求 --length 40 --temperature 1.5
```

手元の結果:

| 温度 | 作られた文章（改行は「/」） |
|---:|---|
| 0.2 | 請求書はどこから変えられますか。よろしくお願いします。/ 昨日から見積書の使い方が分か |
| 0.8 | 請求書の使い方が分かりません。/ 昨日からメールアドレスの確認方法を教えてください。ご |
| 1.5 | 請求書のはあります。よろしくお願いします。/ お世話になっております。ファイルの確認方 |

考察の例:

- 0.2 と 0.8 では、学習した部品どおりの自然な文になりました
- 1.5 では「請求書のはあります。」のように、学習に無い崩れた並びが出ました。確率の低い文字も選ばれやすくなるためです
- 温度で割ると、確率の差が、小さい温度では広がり、大きい温度では縮みます。06-2 で LLM の温度を変えたときと同じ仕組みです

## 3 コンテキストの長さを変える

```python
from roadmap_examples.p05_charlm import Config, template_corpus, train


def test_longer_context_predicts_better() -> None:
    text = template_corpus()
    short = train(text, steps=2000, cfg=Config(context=2))
    long = train(text, steps=2000, cfg=Config(context=16))
    assert long.log[-1][2] < short.log[-1][2]
```

手元の結果（2000 ステップ目の検証の損失）:

| context | 2 | 4 | 16 |
|---|---:|---:|---:|
| 検証の損失 | 0.76 | 0.62 | 0.36 |

考察の例:

- 直前の 2 文字しか見えないと、「の」の次に何が来るかを、前の語（「請求書の」か「プランの」か）で区別できません
- 16 文字あれば、文の頭（「お世話になっております。」の後か、など）まで見えて、次の文字を絞り込めます
- テストは 2 回の学習で 10 秒ほどかかります。CI に入れるなら、ステップ数や文章を小さくして数秒に収めます

## 4 PyTorch の版で層の数を変える（任意）

本文の例で、`CharLM(len(vocab.chars), layers=1)` にして動かし、パラメーターの数を数えます。

```python
print(sum(p.numel() for p in model.parameters()))
```

手元の結果:

| layers | パラメーターの数 | 1000 ステップ目の検証の損失 |
|---:|---:|---:|
| 1 | 66,608 | 0.30 |
| 2 | 116,592 | 0.29 |

考察の例:

- 層を 1 つ足すと、パラメーターは約 5 万個増えます（アテンションと全結合の重み）
- この文章では、損失はほとんど変わりませんでした。部品の組み合わせ方が単純で、1 層で学びきれるためです
- 検証の損失は、ランダムに選んだ 1 つのミニバッチで測っているので、0.01 ほどの差はばらつきの範囲です。
  比べるときは、演習のコード（NumPy の版）の `mean_loss` のように、検証の全部で測ります
