## 1 ReLU に替える

```python
import numpy as np
import pytest

from roadmap_examples.p05_mlp import Params, init_params, numerical_grad, softmax


def loss_and_grads_relu(params: Params, x: np.ndarray, y: np.ndarray) -> tuple[float, Params]:
    z1 = x @ params["w1"] + params["b1"]
    h = np.maximum(z1, 0.0)
    probs = softmax(h @ params["w2"] + params["b2"])
    n = len(y)
    loss = float(-np.log(probs[np.arange(n), y] + 1e-12).mean())
    dz2 = probs.copy()
    dz2[np.arange(n), y] -= 1.0
    dz2 /= n
    grads = {"w2": h.T @ dz2, "b2": dz2.sum(axis=0)}
    dz1 = (dz2 @ params["w2"].T) * (z1 > 0)  # ReLU の微分: 正なら 1、そうでなければ 0
    grads["w1"] = x.T @ dz1
    grads["b1"] = dz1.sum(axis=0)
    return loss, grads


def test_relu_gradients() -> None:
    rng = np.random.default_rng(2)
    params = init_params(3, 5, 4, seed=2)
    x, y = rng.normal(size=(6, 3)), np.array([0, 1, 2, 3, 1, 0])
    _, grads = loss_and_grads_relu(params, x, y)
    for name, p in params.items():
        expected = numerical_grad(lambda: loss_and_grads_relu(params, x, y)[0], p)
        assert grads[name] == pytest.approx(expected, abs=1e-6), name
```

なぜこうするか:

- `tanh` の微分は出力 `h` から計算できました（`1 - h²`）。ReLU の微分は「入力 `z1` が正かどうか」で決まるので、`z1` を残しておきます
- ReLU は 0 のところで折れ曲がり、微分できません。`z1` がちょうど 0 に近い要素があると、数値微分とずれることがあります。
  確かめるときは、乱数の入力で、0 ちょうどの値が出にくいようにします
- ReLU は、正の側で微分が常に 1 なので、層を深くしても勾配が小さくなりにくい、という理由でよく使われます

## 2 学習率を変える

```python
from roadmap_examples.p05_mlp import XOR_X, XOR_Y, predict, train_xor


def test_learning_rate() -> None:
    small, _ = train_xor(lr=0.01)
    good, _ = train_xor(lr=0.5)
    large, _ = train_xor(lr=5.0)
    assert (predict(good, XOR_X) == XOR_Y).all()
    assert not (predict(small, XOR_X) == XOR_Y).all()
    assert not (predict(large, XOR_X) == XOR_Y).all()
```

手元の結果:

| 学習率 | 最後の損失 | 予測（正解は 0・1・1・0） |
|---:|---:|---|
| 0.01 | 0.534 | 0・1・1・1 |
| 0.5 | 0.001 | 0・1・1・0 |
| 5.0 | 1.560 | 0・1・0・0 |

考察の例:

- 小さすぎると、2000 回では損失が下がりきりません。回数を増やせば、いずれ学習できる見込みはあります
- 大きすぎると、1 回の更新で谷を飛び越えてしまい、損失が下がらず、最初（約 0.74）より大きくなりました
- ちょうど良い学習率は、モデルとデータで変わります。損失の推移を記録して、下がり方を見て決めます（05-2 の Adam は、この調整を少し楽にします）

## 3 隠れ層の大きさを変える

```python
from roadmap_examples.p05_mlp import XOR_X, XOR_Y, predict, train_xor


def solved(n_hidden: int) -> int:
    return sum(bool((predict(train_xor(n_hidden=n_hidden, seed=s)[0], XOR_X) == XOR_Y).all()) for s in range(10))


def test_hidden_size() -> None:
    assert solved(1) == 0
    assert solved(4) == 10
```

手元の結果:

| 隠れ層の素子の数 | 1 | 2 | 3 | 4 |
|---|---:|---:|---:|---:|
| 10 回中、全部当てた回数 | 0 | 6 | 9 | 10 |

考察の例:

- 素子が 1 個では、XOR を表せません。隠れ層が 1 本の曲がった線しか作れないためです
- 2 個で表せるはずですが、乱数の種によっては、途中の悪い場所（局所的な最小）で止まります
- 素子に余裕があると、どこから始めても学習しやすくなります。大きなモデルが学習しやすい理由の 1 つです
