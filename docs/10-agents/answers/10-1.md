# 10-1 解答

[10-1 エージェントのループとワークフローの違い](../10-1-loop-vs-workflow.md) の演習の解答の一例です。

## 1 同じ題名の課題を作らない

```python
from roadmap_examples.llm import FakeLLM
from roadmap_examples.p08_chunk import load_chunks
from roadmap_examples.p08_rag import DEFAULT_DOCS, NO_ANSWER
from roadmap_examples.p08_search import BM25
from roadmap_examples.p10_agent import ApprovalRequest, Decision, MemoryIssueTracker
from roadmap_examples.p10_workflow import answer_or_file, draft_issue


class Approve:
    def review(self, request: ApprovalRequest) -> Decision | None:
        return Decision(True)


def test_existing_issue_is_reused() -> None:
    question = "この画面は、どのブラウザに対応していますか？"
    tracker = MemoryIssueTracker()
    existing = tracker.create(*draft_issue(question))
    retriever = BM25(load_chunks(DEFAULT_DOCS))
    result = answer_or_file(question, retriever, FakeLLM.of([NO_ANSWER]), tracker, Approve())
    assert result.issue == existing
    assert len(tracker.issues) == 1
```

なぜこうするか:

- 先に入れる課題は、`draft_issue` で作っています。題名の作り方をテストに写すと、作り方を変えたときにテストだけが古くなるからです
- 件数（1 件のまま）も確かめます。「同じものを返した」だけでは、裏で 2 件目を作っていても気づけません

## 2 2 回検索してから答える台本

```python
from roadmap_examples.ollama_client import ChatTurn, ToolCall
from roadmap_examples.p07_tools import FakeToolChat
from roadmap_examples.p08_chunk import load_chunks
from roadmap_examples.p08_rag import DEFAULT_DOCS
from roadmap_examples.p08_search import BM25
from roadmap_examples.p10_agent import MemoryIssueTracker, RecordingApprover, qa_tools, run_agent, start_state


def test_search_twice_then_answer() -> None:
    chat = FakeToolChat(
        [
            ChatTurn("", [ToolCall("search_docs", {"query": "呼びすぎ"})], 100, 10),
            ChatTurn("", [ToolCall("search_docs", {"query": "回数の制限"})], 200, 10),
            ChatTurn("1 分間に 60 回までです（02-api.md）", [], 300, 20),
        ]
    )
    approver = RecordingApprover()
    tools = qa_tools(BM25(load_chunks(DEFAULT_DOCS)), MemoryIssueTracker())
    state = run_agent(chat, start_state("API を呼びすぎたらどうなりますか？"), tools, approver)
    assert (state.steps, len(state.events), len(approver.requests)) == (3, 2, 0)
    assert [e["arguments"]["query"] for e in state.events] == ["呼びすぎ", "回数の制限"]
```

なぜこうするか:

- 承認の係には `RecordingApprover` を使いました。もし誤って承認を頼んだら、`requests` に残るので、0 件であることを確かめられます
- 検索の語の順番も確かめています。台本の 2 回目の結果が、会話に正しく積まれているかの手がかりになります

## 3 ワークフローとエージェントを比べる（任意）

ワークフローは、Python から呼びます（`examples/` で実行）。

```python
from pathlib import Path

from roadmap_examples.llm import LimitedLLM
from roadmap_examples.ollama_client import OllamaChat
from roadmap_examples.p08_chunk import load_chunks
from roadmap_examples.p08_rag import DEFAULT_DOCS
from roadmap_examples.p08_search import BM25
from roadmap_examples.p10_agent import ConsoleApprover, FileIssueTracker
from roadmap_examples.p10_workflow import answer_or_file

llm = LimitedLLM(OllamaChat("<モデル名>", options={"temperature": 0}), max_calls=1, max_tokens=20_000)
result = answer_or_file(
    "<質問>", BM25(load_chunks(DEFAULT_DOCS)), llm, FileIssueTracker(Path("issues.jsonl")), ConsoleApprover()
)
print(result.answer.text, result.answer.input_tokens, result.answer.output_tokens, llm.calls)
```

エージェントは本文のコマンドで動かし、最後の行の往復の回数とトークン数を写します。表は次の形にします（値は環境で変わるので、形だけを示します）。

| 質問 | 作り方 | LLM を呼んだ回数 | トークン（入力 / 出力） | 起票の提案 |
|---|---|---:|---|---|
| 資料に答えがある | ワークフロー | 1 | （値） | なし |
| 資料に答えがある | エージェント | （値） | （値） | （あり・なし） |
| 資料に無い（起票は頼んでいない） | ワークフロー | 1 | （値） | あり（いつも提案する） |
| 資料に無い（起票は頼んでいない） | エージェント | （値） | （値） | （あり・なし） |

考察で見ること:

- ワークフローは呼ぶ回数がいつも 1 回で、費用が読みやすい。代わりに、起票を望んでいなくても提案する
- エージェントは、起票を頼まれていない質問で提案しないかもしれない（それが望ましい動き）。その分、往復とトークンが増える
- どちらが向くかは、「起票を望むかどうか」を入力から判断する必要があるかで決まります
