# 10-5 解答

[10-5 AI コーディング支援を開発で使う](../10-5-ai-coding.md) の演習の解答の一例です。

## 1 依頼文と、先に書くテスト

依頼文の例:

```text
目的:
  10 のエージェントで、1 回の実行で起票できる課題を 1 件までにしたい。

やること:
  examples/src/roadmap_examples/p10_agent.py に、承認の係（Approver）を包むクラス AtMostOne を足す。
  中の承認の係が 1 件承認した後は、人に聞かずにすべて却下する（comment に理由を書く）。

制約:
  - run_agent・handle_call・process_pending は変えない
  - 依存を足さない。テストと検査の設定（pyproject.toml・ruff.toml・conftest.py）は変えない
  - 既存のテストは消さない・弱めない

確かめ方:
  - examples/tests/test_p10_agent.py に足したテスト test_second_issue_is_denied_without_asking が通る
  - examples/ で uv run pytest と uv run ruff check .. と uv run ruff format --check .. が通る
```

先に書くテストは、10-4 の解答 1 の `test_second_issue_is_denied_without_asking` と同じです。AI に渡す前に自分で書き、
`AtMostOne` が無いので失敗することを確かめてから渡します。

なぜこうするか:

- 「変えないもの」を名前で書くと、ループを書き換える案を防げます
- 確かめ方にコマンドまで書くと、AI の作業の終わりがはっきりし、人も同じコマンドで確かめられます
- テストが先に失敗することを確かめておくと、「何もしなくても通るテスト」を仕様にしてしまう誤りを防げます

## 2 差分のレビュー

問題点:

| 観点 | 問題 |
|---|---|
| 頼んだ範囲か | 「上限で止まったときも答えを返す」は、上限をなくすことではない。上限という安全の仕組みを外している |
| テストが意味を持つか | テストを `assert True` にして、上限の確かめを消している |
| 失敗の扱い | 止まったときの理由（`stop_reason`）も残らなくなる |

直してもらう依頼の例:

```text
この差分は採りません。上限は外さないでください。
上限で止まったときは、止まった理由と、それまでに検索で見つけた出典を、答えの代わりに表示してください。
limit_reached と既存のテスト（test_stops_at_*）は変えず、format_run の表示だけを変えてください。
表示を確かめるテストを、examples/tests/test_p10_agent.py に足してください。
```

なぜこうするか:

- 頼んだ人の本当の困りごと（止まると何も返らない）を、安全の仕組みを外さずに解く方向を示しています
- 「変えないもの」と「確かめ方」を、もう一度はっきり書きます。最初の依頼であいまいだった部分が、誤った差分の原因になったからです

## 3 権限の確かめ（表の例）

| 権限 | いまの設定 | 足りないところと、手順での補い方 |
|---|---|---|
| 読めるファイル | （例: 開いたフォルダの中だけ） | `.env` が同じフォルダにある。読ませない設定ができなければ、作業中は `.env` を別の場所に置く |
| 書けるファイル | （例: 開いたフォルダの中だけ） | 作業用のブランチで作業し、取り込みの前に人が差分を見る |
| 実行できるコマンド | （例: 毎回確認する） | テストと静的解析だけを確認なしにする。削除・ネットワーク・配備は毎回確認のまま |
| 秘密情報 | （例: 本番の鍵は手元に無い） | 試すときはテスト用の値だけを使う |
| 共有の操作 | （例: push は人が行う） | AI に push や取り込みを頼まない |

設定の名前と場所は道具ごとに違うので、表には「何ができる設定になっているか」を書きます。使う道具の公式のドキュメントで確かめてください。
