## 1 承認を後で決める CLI の設計

承認の係を 2 つ足し、`main` で使い分けます。

```python
from dataclasses import dataclass

from roadmap_examples.p10_agent import ApprovalRequest, Decision


class LaterApprover:
    """いつも「まだ決めていない」を返す（承認待ちで止めるため）."""

    def review(self, request: ApprovalRequest) -> Decision | None:
        return None


@dataclass
class FixedApprover:
    """--decision で決めた答えを、1 回だけ返す. 2 回目からは「まだ決めていない」."""

    decision: Decision
    used: bool = False

    def review(self, request: ApprovalRequest) -> Decision | None:
        if self.used:
            return None
        self.used = True
        return self.decision
```

`main` の下書きです（変えるところだけ）。

```python
from roadmap_examples.p10_state import WAITING, load_state, save_state

if args.resume:
    state = load_state(args.resume)
    approver = FixedApprover(Decision(args.decision == "approve", "CLI で決めた"))
else:
    state = start_state(args.question)
    approver = LaterApprover() if args.state else ConsoleApprover(out=stdout)
state = run_agent(chat, state, tools, approver, limits)
if state.status == WAITING:
    save_state(state, args.state or args.resume)
    print(f"承認を待っています: {state.pending[0]}", file=stdout)
```

なぜこうするか:

- `run_agent` は、承認待ちの状態を渡すと続きから動く作りなので、ループには手を入れずに済みます
- `FixedApprover` を 1 回だけにしているのは、続きの中でモデルがもう一度起票しようとしたとき、前の承認を使い回さないためです。
  1 回の承認は、見せた 1 件の引数にだけ有効にします
- 本番では、保存先をデータベースにし、だれが承認したかも状態に残します。`--decision` を渡せる人を限る仕組み（ログイン）も要ります

## 2 system が無い会話を削る

```python
from roadmap_examples.p10_state import trim_messages

ASK = {"role": "user", "content": "依頼"}


def test_trim_without_system_keeps_first_request() -> None:
    messages = [ASK] + [{"role": "assistant", "content": str(i)} for i in range(5)]
    trimmed = trim_messages(messages, keep_last=2)
    assert trimmed[0] == ASK
    assert [m["content"] for m in trimmed[1:]] == ["3", "4"]
```

なぜこうするか:

- 先頭が system でなければ、先頭の 1 件（依頼）だけを残す作りなので、その分かれ道を確かめています
- 残る件数だけでなく、どれが残ったか（新しい 2 件）まで確かめると、削る向きの誤り（新しいものを消す）にも気づけます

## 3 却下したときの動き（任意）

本文のコマンドで動かし、承認の画面で `N` を答えます。最後の「ツールの記録」に `→ denied（却下）` と出ます。

会話に却下の理由が入っていることは、次のように確かめられます（Python から動かす場合）。

```python
for m in state.messages:
    if m["role"] == "tool" and "承認しなかった" in m["content"]:
        print(m["content"])
```

記録の例（モデルの答えはモデルで変わります）:

| 項目 | 内容 |
|---|---|
| ツールの記録 | `create_issue {...} → denied（却下）` |
| 会話に入った結果 | `{"error": "人が承認しなかったので、実行していません", "comment": "人が承認しませんでした"}` |
| モデルの次の答え | （例: 「起票は見送りました。資料には記載がありません。」） |
| 条件 | モデル名・質問 |

モデルが却下を無視して、もう一度同じ起票をしようとする場合もあります。そのときも承認の画面がもう一度出るので、勝手に起票されることはありません。
何度も繰り返すなら、往復の上限（10-4）で止まります。
