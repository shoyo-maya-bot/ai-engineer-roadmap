# 10-4 解答

[10-4 人の承認・回数と費用の上限](../10-4-approval-limits.md) の演習の解答の一例です。

## 1 1 回の実行で起票は 1 件まで

```python
from dataclasses import dataclass

from roadmap_examples.ollama_client import ChatTurn, ToolCall
from roadmap_examples.p07_tools import FakeToolChat
from roadmap_examples.p08_chunk import load_chunks
from roadmap_examples.p08_rag import DEFAULT_DOCS
from roadmap_examples.p08_search import BM25
from roadmap_examples.p10_agent import (
    ApprovalRequest,
    Approver,
    Decision,
    MemoryIssueTracker,
    qa_tools,
    run_agent,
    start_state,
)


@dataclass
class AtMostOne:
    """中の承認の係に聞くのは、承認が 1 件出るまで. その後はすべて却下する."""

    inner: Approver
    approved: int = 0

    def review(self, request: ApprovalRequest) -> Decision | None:
        if self.approved >= 1:
            return Decision(False, "1 回の実行で起票できるのは 1 件までです")
        decision = self.inner.review(request)
        if decision is not None and decision.approved:
            self.approved += 1
        return decision


class CountingApprover:
    def __init__(self) -> None:
        self.asked = 0

    def review(self, request: ApprovalRequest) -> Decision | None:
        self.asked += 1
        return Decision(True)


def issue(title: str) -> ChatTurn:
    return ChatTurn("", [ToolCall("create_issue", {"title": title, "body": "質問"})], 10, 1)


def test_second_issue_is_denied_without_asking() -> None:
    tracker = MemoryIssueTracker()
    human = CountingApprover()
    chat = FakeToolChat([issue("1 件目"), issue("2 件目"), ChatTurn("1 件だけ起票しました", [], 10, 1)])
    tools = qa_tools(BM25(load_chunks(DEFAULT_DOCS)), tracker)
    state = run_agent(chat, start_state("起票して"), tools, AtMostOne(human))
    assert [i.title for i in tracker.issues] == ["1 件目"]
    assert human.asked == 1
    assert [e["status"] for e in state.events] == ["ok", "denied"]
```

なぜこうするか:

- `run_agent` を直さずに、承認の係を包むだけで決まりを足しています。決まりを増やすたびにループを直すと、ループのテストもやり直しになります
- 2 回目は人に聞かずに却下します。決まりで却下できるものは、人の手をわずらわせません
- 却下の理由（`comment`）はモデルに伝わるので、モデルは「1 件だけ起票した」と答えられます

## 2 評価セットに 2 件足す

```python
from roadmap_examples.evalset import EvalCase, load_cases, run_eval
from roadmap_examples.ollama_client import ChatTurn, ToolCall
from roadmap_examples.p07_tools import FakeToolChat
from roadmap_examples.p10_eval import DEFAULT_EVAL, agent_score, make_predict

MORE = [
    EvalCase(
        "u01",
        "備品は何日間借りられますか？記載がなければ課題にしてください。",
        {"issue": False, "tools": ["search_docs"], "keywords": ["14 日"]},
        ("起票を頼まれた", "答えがある"),
    ),
    EvalCase(
        "u02",
        "この画面は、どのブラウザに対応していますか？",
        {"issue": False, "tools": ["search_docs"]},
        ("起票を頼まれていない",),
    ),
]
SEARCH = ChatTurn("", [ToolCall("search_docs", {"query": "q"})], 100, 10)
ISSUE = ChatTurn("", [ToolCall("create_issue", {"title": "記載なし", "body": "質問"})], 100, 10)


def test_more_cases() -> None:
    cases = load_cases(DEFAULT_EVAL) + MORE
    assert len({c.id for c in cases}) == 10
    good = {"u01": [SEARCH, ChatTurn("14 日です", [], 10, 1)], "u02": [SEARCH, ChatTurn("記載がありません", [], 10, 1)]}
    bad = {
        "u01": [SEARCH, ISSUE, ChatTurn("起票しました", [], 10, 1)],
        "u02": [ISSUE, ChatTurn("起票しました", [], 10, 1)],
    }
    good_report = run_eval(MORE, make_predict(lambda c: FakeToolChat(list(good[c.id]))), agent_score)
    bad_report = run_eval(MORE, make_predict(lambda c: FakeToolChat(list(bad[c.id]))), agent_score)
    assert good_report.mean == 1.0
    assert {r.id: r.score for r in bad_report.results} == {"u01": 0.6, "u02": 0.5}
```

なぜこうするか:

- u01 は「起票を頼まれたが、資料に答えがある」件です。答えがあれば起票は要らない、という判断を確かめます
- u02 は、a05 と同じ質問で、起票を頼んでいない版です。a05 と組にすると、頼んだかどうかだけで動きが変わるかを確かめられます
- 外れる台本の点を、確かめごとの数から計算しておきます。u01 は 5 項目（答えの語を含む）のうち「起票の提案」と「答えの語」が外れて 0.6、
  u02 は 4 項目のうち「起票の提案」と「呼ぶべきツール」が外れて 0.5 です

## 3 手元で評価を流す（任意）

```bash
uv run python -m roadmap_examples.p10_eval --model <ツールに対応したモデル名>
```

表の形は本文のとおりです。直す前と後を並べます（値はモデルで変わるので、形だけを示します）。

| 項目 | 直す前 | 直した後 |
|---|---|---|
| 点の平均 | （値） | （値） |
| 外れた件 | （例: a06: 起票の提案） | （値） |
| 直した内容 | — | （例: `SYSTEM` の決まり 3 に「頼まれていなければ、起票を提案しない」を足した） |
| 条件 | モデル名・上限 | 同じ |

考察で見ること:

- 直した件が良くなったか。ほかの件（特に「起票を頼まれた」の件）が悪くなっていないか
- 1 回では偶然かもしれません。同じ評価を 2〜3 回流し、ぶれの大きさも見ます（06-2 の temperature）
