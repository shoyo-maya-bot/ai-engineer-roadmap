# 10-3 解答

[10-3 MCP でツールをつなぐ](../10-3-mcp.md) の演習の解答の一例です。

## 1 読むだけのツール list_docs を足す

```python
from pathlib import Path

from roadmap_examples.p07_tools import Tool
from roadmap_examples.p08_rag import DEFAULT_DOCS
from roadmap_examples.p10_mcp import InProcessTransport, McpClient, build_server


def list_docs() -> dict[str, list[str]]:
    return {"docs": sorted(p.name for p in DEFAULT_DOCS.glob("*.md"))}


LIST_DOCS = Tool(
    "list_docs",
    "設計書のファイル名の一覧を返す. 読むだけ",
    {"type": "object", "additionalProperties": False},
    list_docs,
)


def test_list_docs_tool(tmp_path: Path) -> None:
    server = build_server(tmp_path / "issues.jsonl")
    server.tools.append(LIST_DOCS)
    server.annotations["list_docs"] = {"readOnlyHint": True, "openWorldHint": False}
    client = McpClient(InProcessTransport(server))
    assert "list_docs" in [t["name"] for t in client.list_tools()]
    result = client.call_tool("list_docs", {})
    assert result["isError"] is False
    assert '"01-overview.md"' in result["content"][0]["text"]
    assert client.call_tool("list_docs", {"x": 1})["isError"] is True  # 余計な引数は実行の誤り
```

なぜこうするか:

- 引数なしのツールは、仕様が勧める `{"type": "object", "additionalProperties": false}` にしました。空の引数だけを受け付けます
- 余計な引数を渡したときに、プロトコルの誤りではなく `isError: true` になることも確かめています。07-2 の `validate` が引数を確かめ、誤りをモデルに返す形です
- エージェントで使うなら、ホストの許可リスト（`read_only`）にも `list_docs` を足します。注釈の `readOnlyHint` だけでは、承認は省かれません

## 2 対応していない版のときに送り直す

```python
from pathlib import Path

from roadmap_examples.p10_mcp import UNSUPPORTED_PROTOCOL_VERSION, InProcessTransport, McpClient, McpError, build_server

KNOWN = ["2026-07-28"]  # このクライアントが対応している版


class RetryingClient(McpClient):
    def call(self, method, params=None):
        try:
            return super().call(method, params)
        except McpError as e:
            if e.code != UNSUPPORTED_PROTOCOL_VERSION:
                raise
            common = [v for v in (e.data or {}).get("supported", []) if v in KNOWN]
            if not common:
                raise
            self.protocol_version = common[0]
            return super().call(method, params)  # 送り直すのは 1 回だけ


def test_retry_with_supported_version(tmp_path: Path) -> None:
    client = RetryingClient(InProcessTransport(build_server(tmp_path / "i.jsonl")), protocol_version="1900-01-01")
    assert client.discover()["supportedVersions"] == ["2026-07-28"]
    assert client.protocol_version == "2026-07-28"
    assert client.next_id == 3  # 1 回目（断られた）と 2 回目（送り直し）
```

なぜこうするか:

- 仕様は、クライアントが `supported` の一覧から両方が対応している版を選び、送り直すよう勧めています（[仕様: 版と互換性](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning)）
- 送り直しを 1 回だけにしています。2 回目も断られたら例外のまま上げ、何度も送り続けないようにします
- 送り直すときは、新しい `id` を使います（`call` が毎回 `next_id` を進めます）。応答を待っている要求と同じ `id` を使わないのは、仕様の決まりです（[仕様: 基本のプロトコル](https://modelcontextprotocol.io/specification/2026-07-28/basic)）
- 決めた版は `protocol_version` に覚えておき、次の要求からはその版で送ります

## 3 公式の SDK で書く（任意）

この教材のリポジトリとは別の作業フォルダで試します（`examples/` の依存に SDK を足さないため）。

```bash
mkdir <作業フォルダ>/mcp-try && cd <作業フォルダ>/mcp-try
uv init
uv add "mcp[cli]"
```

サーバーとクライアントは、本文の例をもとに書きます。`search_docs` の中身は、08 の設計書を読んで語で探す簡単なもので構いません。
確かめることは次の 3 つです。

- クライアントの `list_tools()` に `search_docs` が出る
- `call_tool("search_docs", {"query": "アクセストークン"})` の結果に、設計書の文章が入る
- サーバーで `print` を使わず、ログを標準エラー（`logging`）に出しても、やり取りが壊れない（[公式ドキュメント: サーバーを動かす](https://py.sdk.modelcontextprotocol.io/run/) の注意）

SDK の使い方は版で変わることがあります。動かないときは、入った版の公式ドキュメントで確かめます。
