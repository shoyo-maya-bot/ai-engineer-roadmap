# 08-3 解答

[08-3 ベクトル検索・ハイブリッド検索・並べ替え](../08-3-search.md) の演習の解答の一例です。

## 1 3 つの検索を比べる

```python
from roadmap_examples.evalset import load_cases
from roadmap_examples.p08_chunk import load_chunks
from roadmap_examples.p08_eval import DEFAULT_EVAL, eval_retrieval
from roadmap_examples.p08_rag import DEFAULT_DOCS
from roadmap_examples.p08_search import BM25, FakeEmbedder, HybridRetriever, VectorIndex

cases = load_cases(DEFAULT_EVAL)
chunks = load_chunks(DEFAULT_DOCS)
vector = VectorIndex(FakeEmbedder(), chunks)
bm25 = BM25(chunks)
retrievers = {"ベクトル（Fake）": vector, "BM25": bm25, "ハイブリッド": HybridRetriever(vector, bm25)}
for name, retriever in retrievers.items():
    at1 = eval_retrieval(cases, retriever, k=1)
    at4 = eval_retrieval(cases, retriever, k=4)
    missed = [r.id for r in at1.results if r.score < 1]
    print(f"{name}: recall@1 {at1.mean:.3f} / recall@4 {at4.mean:.3f} / @1 で外れた {missed}")
```

結果（条件: 題材の設計書 4 文書・17 チャンク、`max_chars=400`・`overlap=50`、評価セットの資料に答えがある 12 問。`FakeEmbedder` は毎回同じ結果になります）:

| 検索 | recall@1 | recall@4 | @1 で外れた問い |
|---|---|---|---|
| ベクトル（Fake） | 0.875 | 0.958 | q02・q11 |
| BM25 | 0.875 | 1.000 | q02・q11 |
| ハイブリッド | 0.792 | 1.000 | q02・q05・q11 |

読み取れること:

- q11 は根拠が 2 文書なので、k=1 では最高でも 0.5 点です。複数の文書にまたがる質問は、k を小さくすると必ず落ちます
- ハイブリッドは recall@1 では下がりました。RRF は「両方の一覧に出たもの」を上げるので、片方だけが 1 位にしたチャンクが下がることがあります。
  ハイブリッドがいつも良いわけではなく、k を含めて評価で決めます
- `FakeEmbedder` は語の重なりしか見ないので、ここでのベクトル検索は BM25 に近い動きです。この表から「ベクトル検索の良し悪し」は言えません（3 で本物と比べます）

## 2 BM25 の b を変える

```python
for b in (0.0, 0.75, 1.0):
    report = eval_retrieval(cases, BM25(chunks, b=b), k=1)
    print(f"b={b}: recall@1 {report.mean:.3f}")
```

結果（条件は 1 と同じ）: b=0 で 0.833、b=0.75 と b=1 で 0.875 でした。
長さの補正が無い（b=0）と、長いチャンク（表の多い節）が、語が多いぶん上に来やすくなります。
この評価セットでは差は 1 問の半分（q11）だけなので、b は既定の 0.75 のままにします。
件数の少ない評価セットでの小さな差は、たまたまのことがあります。評価セットを増やしてから判断します。

## 3 本物のエンベディングで比べる（任意）

```python
from roadmap_examples.ollama_client import OllamaEmbedder

real = VectorIndex(OllamaEmbedder("<エンベディングのモデル名>"), chunks)
for name, retriever in {"ベクトル（本物）": real, "ハイブリッド（本物）": HybridRetriever(real, bm25)}.items():
    at1 = eval_retrieval(cases, retriever, k=1)
    print(name, f"{at1.mean:.3f}", {r.id: r.score for r in at1.results if r.id in ("q05", "q06", "q10")})
```

考察で見るところ:

- 「言い換え」の質問（q05「呼びすぎたら」・q06「知らせるメール」・q10「夜中に」）が、本物のエンベディングで当たるようになったか。
  資料と同じ語が少ない質問は、意味の近さを見るベクトル検索の出番です
- `E-302` の質問（q12）は、本物のエンベディングでも当たるか。外れるなら、BM25 を合わせる理由になります
- 表には、使ったモデル名を書きます。モデルを替えると結果も変わります
