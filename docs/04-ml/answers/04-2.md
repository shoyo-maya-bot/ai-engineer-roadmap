## 1 規則を変えて、必要な深さを確かめる

```python
from sklearn.tree import DecisionTreeClassifier

from roadmap_examples.p04_trees import INQUIRIES, MONTHS


def new_table() -> tuple[list[list[int]], list[int]]:
    x = [[m, q] for m in MONTHS for q in INQUIRIES]
    return x, [int(m >= 12 and q >= 4) for m, q in x]


def test_min_depth() -> None:
    x, y = new_table()
    scores = {d: DecisionTreeClassifier(max_depth=d, random_state=0).fit(x, y).score(x, y) for d in range(1, 5)}
    assert min(d for d, s in scores.items() if s == 1.0) == 2
```

なぜこうするか:

- 「A かつ B」の規則は、A で分けた先で B で分ければ表せるので、深さ 2 で足ります。深さ 1 の正解率は手元で 86.7% でした
- 本文の規則（利用月数によって問い合わせ数の効き方が逆になる）は、深さ 3 が要りました。規則の形で、必要な深さが変わります
- 学習データの正解率が 1.0 になる深さは、「表せるか」の目安です。新しいデータでの良さは、04-4 の交差検証で測ります

## 2 ロジスティック回帰に組み合わせの列を足す

```python
from sklearn.linear_model import LogisticRegression

from roadmap_examples.p04_trees import churn_table


def test_feature_engineering_helps_a_linear_model() -> None:
    x, y = churn_table()
    plain = LogisticRegression(max_iter=1000).fit(x, y).score(x, y)
    x2 = [[m, q, m * q] for m, q in x]  # 掛け算の列を足す
    product = LogisticRegression(max_iter=1000).fit(x2, y).score(x2, y)
    x3 = [[m, q, int(m < 6) * q, int(m >= 6) * int(q == 0)] for m, q in x]  # 規則の形を知っている列
    designed = LogisticRegression(max_iter=1000).fit(x3, y).score(x3, y)
    assert plain < product < designed
```

手元では 83.3% → 93.3% → 96.7% でした。

考察の例:

- 掛け算の列で、「利用月数によって問い合わせ数の効き方が変わる」を少し表せるようになります
- 規則の形を知っていれば、それに合う列を作って、線形のモデルでもほぼ表せます。ただし、本番では規則の形が分からないことが普通です
- 決定木は、こうした組み合わせを自分で探します。線形のモデルは、組み合わせを人が特徴量として作る必要があります

## 3 並べ替えの重要度を自分で測る

```python
import numpy as np

from roadmap_examples.evalset import load_cases
from roadmap_examples.p04_classify import DEFAULT_EVAL, DEFAULT_TRAIN, texts_and_labels, train
from roadmap_examples.p04_trees import text_models


def permutation_drop(n_top: int = 10, repeats: int = 5, seed: int = 0) -> list[tuple[str, float, float]]:
    """重要度の上位 n_top の列を、評価セットの中で混ぜたときの正解率の下がり方（文字の組, 重要度, 下がり方の平均）."""
    forest = train(load_cases(DEFAULT_TRAIN), text_models()["ランダムフォレスト"])
    tfidf, clf = forest.named_steps["tfidf"], forest.named_steps["clf"]
    texts, labels = texts_and_labels(load_cases(DEFAULT_EVAL))
    x = tfidf.transform(texts).toarray()
    base = clf.score(x, labels)
    names = tfidf.get_feature_names_out()
    rng = np.random.default_rng(seed)
    rows = []
    for col in clf.feature_importances_.argsort()[::-1][:n_top]:
        drops = []
        for _ in range(repeats):
            shuffled = x.copy()
            shuffled[:, col] = rng.permutation(shuffled[:, col])  # この列だけ、件の間で混ぜる
            drops.append(base - clf.score(shuffled, labels))
        rows.append((str(names[col]), float(clf.feature_importances_[col]), float(np.mean(drops))))
    return rows


def test_permutation_drop_is_small_for_common_chars() -> None:
    rows = permutation_drop()
    assert len(rows) == 10
    assert all(abs(drop) < 0.1 for _, _, drop in rows)
```

手元の結果（上位 5 つ）:

| 文字の組 | 不純度にもとづく重要度 | 混ぜたときの正解率の下がり方 |
|---|---:|---:|
| た | 0.020 | 0.007 |
| が | 0.018 | 0.000 |
| い | 0.017 | 0.000 |
| 。 | 0.017 | -0.013 |
| す | 0.016 | 0.007 |

考察の例:

- 不純度にもとづく重要度の上位でも、評価セットで混ぜても正解率はほとんど変わりません（30 件の 1 件が 0.033）
- 「。」のように、混ぜるとかえって正解率が上がる（下がり方がマイナス）ものもあります。この列は、新しいデータでの予測には役立っていません
- 重要度で「モデルが何を見ているか」を説明するときは、学習に使っていないデータでの並べ替えの重要度も添えます
