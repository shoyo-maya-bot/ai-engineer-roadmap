## 1 文字数だけの回帰と比べる

```python
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_absolute_error

from roadmap_examples.p04_regression import HANDLING, TEST, fit_and_score, to_xy


def test_attachments_matter() -> None:
    x, y = to_xy(HANDLING)
    x_test, y_test = to_xy(TEST)
    chars_only = LinearRegression().fit(x[:, :1], y)  # 1 列目（文字数）だけ
    mae_chars = mean_absolute_error(y_test, chars_only.predict(x_test[:, :1]))
    _, both = fit_and_score()
    assert both.mae < 1.0 < mae_chars
```

手元では、文字数だけのモデルの MAE は約 4.7 分、両方を使うモデルは約 0.4 分でした。

なぜこうするか:

- 列の取り出し方（`x[:, :1]`）を、学習とテストでそろえます。`x[:, 0]` だと 1 次元の配列になり、`fit` が受け取れません
- このデータでは、添付が 1 つ増えると約 8 分増えます。添付の数を入れないと、その差を文字数だけで説明しようとして外れます
- 特徴量を足すほど良いとは限りません。足した特徴量が予測に効くかは、学習に使っていないデータの誤差で確かめます

## 2 文字の組の長さを変える

```python
import pytest

from roadmap_examples.evalset import exact_match, load_cases, run_eval
from roadmap_examples.p04_classify import DEFAULT_EVAL, DEFAULT_TRAIN, build_model, load_train, model_predict, train


@pytest.mark.parametrize(("ngram", "correct"), [((1, 1), 22), ((1, 2), 24), ((1, 3), 25)])
def test_ngram_range(ngram: tuple[int, int], correct: int) -> None:
    model = train(load_train(DEFAULT_TRAIN), build_model(ngram_range=ngram))
    report = run_eval(load_cases(DEFAULT_EVAL), model_predict(model), exact_match("category"))
    assert sum(r.score for r in report.results) == correct
```

数は手元で実行して確かめた値です。

採用を決めてよいか:

- 差は 30 件中の 1〜3 件（3.3〜10 ポイント）です。評価セットが小さいと、数件の違いで順位が入れ替わります
- 学習データの交差検証（04-4）では、順位が逆で、1 文字だけ（76.2%）がいちばん良く、1〜3 文字（70.8%）がいちばん低くなりました。
  評価セットだけを見て「1〜3 文字が良い」と決めると、30 件にたまたま合った設定を選ぶことになります
- 評価セットの結果を見て設定を選ぶと、その評価セットに合わせ込んだことになります。次に評価セットで測った数字は、楽観的になります
- 設定は、学習データの中の交差検証（04-4）で選び、評価セットは最後に 1 回だけ使います

## 3 確率を読む

```python
from roadmap_examples.p04_classify import DEFAULT_TRAIN, load_train, train

model = train(load_train(DEFAULT_TRAIN))
for text in ["ログインできません", "請求書の画面が固まります", "契約の更新はいつですか"]:
    probs = dict(zip(model.classes_, model.predict_proba([text])[0].round(2), strict=True))
    print(text, probs)
```

手元では次のようになりました（いちばん高い確率を太字にしています）。

| 文 | account | billing | bug | contract | other |
|---|---:|---:|---:|---:|---:|
| ログインできません | **0.41** | 0.12 | 0.22 | 0.13 | 0.11 |
| 請求書の画面が固まります | 0.11 | **0.30** | 0.30 | 0.12 | 0.16 |
| 契約の更新はいつですか | 0.09 | 0.18 | 0.09 | **0.50** | 0.14 |

考察の例:

- いちばん高い確率は、どれも 0.5 前後かそれ未満です。学習データが 130 件と少なく、確率が全体に低く出ます
- 「請求書の画面が固まります」は、07 の判断の基準（画面が動かないなら bug）では bug です。
  モデルは billing と bug の確率がほぼ同じ（どちらも 0.30。小数 3 けた目で billing がわずかに上）で、「請求書」に引かれて billing と答えました
- 2 つの分類の確率が近い文は、紛らわしい件です。こうした文を学習データに足すと、モデルが判断の基準を学べます
