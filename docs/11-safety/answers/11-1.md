# 11-1 解答

## 1 08 の答えの数字を確かめる

```python
from roadmap_examples.llm import FakeLLM
from roadmap_examples.p08_chunk import load_chunks
from roadmap_examples.p08_rag import DEFAULT_DOCS, Answer, answer
from roadmap_examples.p08_search import BM25
from roadmap_examples.p11_numbers import unsupported_numbers


def check_numbers(ans: Answer) -> list[str]:
    """答えの数字のうち、プロンプトに入れた資料に無いもの."""
    return unsupported_numbers(ans.text, [h.chunk.text for h in ans.hits])


def test_number_not_in_documents_is_found() -> None:
    llm = FakeLLM.of(["有効期限は 60 分です [1]"])
    ans = answer("API のアクセストークンは何分で切れますか？", BM25(load_chunks(DEFAULT_DOCS)), llm)
    assert check_numbers(ans) == ["60"]


def test_number_in_documents_is_fine() -> None:
    llm = FakeLLM.of(["有効期限は 30 分です [1]"])
    ans = answer("API のアクセストークンは何分で切れますか？", BM25(load_chunks(DEFAULT_DOCS)), llm)
    assert check_numbers(ans) == []
```

なぜこうするか:

- 比べる相手は、設計書の全部ではなく、**そのときプロンプトに入れた資料** です。モデルが見ていない資料にたまたま同じ数字があっても、根拠にはなりません
- 正しい答え（30 分）では空になることも確かめます。確かめが厳しすぎて、正しい答えまで疑わないかを見るためです
- 本番で使うなら、空でないときに `format_answer`（08）の注意と同じように「資料に無い数字があります」と添えます

## 2 r=4 と r=8 を比べる

```bash
uv run python -m roadmap_examples.p09_lora --rank 4 --out results-r4.jsonl
uv run python -m roadmap_examples.p09_lora --rank 8 --out results-r8.jsonl
uv run python -m roadmap_examples.p11_numbers --before results-r4.jsonl --after results-r8.jsonl
```

```text
前: 正解率 86.7%（26 / 30 件）. 95% の区間: 70.3%〜94.7%
後: 正解率 86.7%（26 / 30 件）. 95% の区間: 70.3%〜94.7%
良くなった件 0 / 悪くなった件 0. 偶然でこれ以上偏る確率: 1.000
```

判断: **r=4 を選ぶ**。

- 件ごとに見ても、答えが変わった件がありません。この評価セットでは、r=8 にしても何も変わっていません
- 差が無いなら、学習する重みが半分（2,176 個と 4,352 個）の r=4 のほうが、学習も保存も軽く済みます
- 09-2 の演習 1 で見たように、乱数の種を変えると r=4 は 1 件ぶれることがあります。種を変えた結果もあわせて判断すると、より確かです

## 3 ベンチマークを読む（任意）

表の形の例です。項目ごとに、公式の説明のどこに書かれていたか（見つからなかったか）も書きます。

| 確かめること | 書いたこと |
|---|---|
| 何を測っているか | （例: 英語の多肢選択の知識問題。4 択） |
| 指標の定義 | （例: 完全一致の正解率） |
| 条件 | （例: 例示 5 件。temperature の記載なし → 「不明」と書く） |
| 件数と幅 | （例: 約 1 万問。幅は狭いが、分野ごとでは数百問） |
| 混入の恐れ | （例: 公開から数年。学習データの説明に除外の記載なし → 恐れあり） |
| 自分の課題との近さ | （例: 日本語の問い合わせの分類とは遠い。候補を絞る目安にとどめる） |

考察で見ること:

- 「不明」が多いベンチマークの点数は、モデルを選ぶ決め手にしません
- 候補を 2〜3 個に絞ったら、自分の評価セット（07 の 30 件など）で比べます
