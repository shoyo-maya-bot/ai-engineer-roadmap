# 09-2 解答

[09-2 SFT・LoRA・QLoRA](../09-2-sft-lora-qlora.md) の演習の解答の一例です。

## 1 r と乱数の種を変える

```bash
for r in 1 2 4 8; do uv run python -m roadmap_examples.p09_lora --rank $r; done
for s in 1 2 3; do uv run python -m roadmap_examples.p09_lora --seed $s; done
```

手元（Linux・CPU）で流した結果です。

| r | 学習する重みの数 | 種 0 | 種 1 | 種 2 |
|---|---|---|---|---|
| 1 | 544 | 56.7% | 43.3% | 53.3% |
| 2 | 1,088 | 76.7% | 76.7% | 76.7% |
| 4 | 2,176 | 86.7% | 83.3% | 86.7% |
| 8 | 4,352 | 86.7% | 86.7% | 86.7% |

r=4 は種 3 でも 86.7% でした。決めた r: **4**。

なぜそう決めるか:

- r=1 は種によって大きくぶれ、調整の前（63.3%）より下がることもあります。差分で表せる変化が足りません
- r=4 と r=8 の差は、30 件中 1 件のぶれの中です。差が無いなら、学習する重みが少ない r=4 を選びます
- 乱数の種を変えて流すのは、1 回だけの結果が偶然よかった（悪かった）だけかを見分けるためです。結果には、試した種の数も書きます

## 2 出力の層にも LoRA を付ける

増える重みの数は、r × (入力 + 出力) = 4 × (32 + 5) = **148 個** です（r=4 のとき。合計 2,176 + 148 = 2,324 個）。

```python
import numpy as np

from roadmap_examples.evalset import load_cases
from roadmap_examples.p07_classify import DEFAULT_EVAL
from roadmap_examples.p09_lora import BASE_TRAIN, LoRA, encode, init_model, softmax, train_full


def test_lora_on_w2_starts_as_the_base_model() -> None:
    base = train_full(init_model(0), *encode(load_cases(BASE_TRAIN)), epochs=50)
    rng = np.random.default_rng(0)
    r = 4
    lora2 = LoRA(rng.normal(0, 1 / np.sqrt(32), (r, 32)), np.zeros((5, r)), alpha=8.0)
    assert lora2.n_params == 148
    x, _ = encode(load_cases(DEFAULT_EVAL))
    h, probs = base.forward(x)
    probs2 = softmax(h @ (base.w2 + lora2.delta()).T + base.b2)
    assert np.array_equal(probs, probs2)
```

なぜこうするか:

- `LoRA` は「r × 入力」の A と「出力 × r」の B を持つだけなので、形を変えれば `w2` にもそのまま使えます
- B が 0 なら差分も 0 なので、確率は 1 つ残らず同じです。`np.allclose` ではなく `np.array_equal` で確かめられます
- 学習まで書くなら、`backward` が返す `w2` の勾配を、`w1` と同じ式で A と B の勾配に直します。PEFT の `target_modules` に層を足すのと同じことです

## 3 SFT の例を読む

```bash
uv run python -m roadmap_examples.p09_sft --out sft.jsonl
```

1 行目（t001）の中身:

| 役割 | 中身 |
|---|---|
| system | 07 の `system_prompt` と同じ（役割・手順・分類の一覧・出力の形）。例示は入らない |
| user | `<inquiry>` と `</inquiry>` で囲んだ問い合わせ文（「今月の請求額が先月より高い理由を知りたいです。」） |
| assistant | 期待する答えの JSON（`{"category": "billing", "reason": "請求額が増えた理由の確認"}`） |

評価セットの 1 件（例: c007「パスワードを忘れてしまいました。」）を学習の例のファイルに足して流すと、次のように止まります（終了コード 1）。

```text
エラー: 評価セットと同じ文章が学習の例にあります（学習に使えません）:
  x1 = c007
```

なぜこう確かめるか:

- prompt と completion に分けておくと、学習の損失は答え（completion）の部分だけで計算されます。問い合わせ文そのものを覚えさせる必要はありません
- 重なりの確かめを書き出しの中に入れておくと、確かめ忘れが起きません
