## 1 3 ビットを足す

`QUANT_ROWS` に 2 行足すと、表に次の行が加わります（09-2 と同じ条件）。

```python
QUANT_ROWS += [("3 ビット・32 個ずつの塊", 3, 32), ("3 ビット・全体で 1 つの倍率", 3, None)]
```

| 重みの持ち方 | w1 の平均のずれ | 正解率 |
|---|---|---|
| 3 ビット・32 個ずつの塊 | 0.0765 | 90.0% |
| 3 ビット・全体で 1 つの倍率 | 0.1421 | 83.3% |

テストです。

```python
import numpy as np

from roadmap_examples.p09_quant import mean_abs_error


def test_three_bits_are_between_four_and_two() -> None:
    w = np.random.default_rng(0).normal(0, 0.02, (32, 512))
    for group in (None, 32):
        assert mean_abs_error(w, 4, group) < mean_abs_error(w, 3, group) < mean_abs_error(w, 2, group)
```

なぜこうするか:

- 3 ビットでは使える整数が -3〜3 の 7 つになり、4 ビット（15 個）より粗くなります。ずれが 4 ビットと 2 ビットの間に入ることを、塊の有無の両方で確かめています
- 全体で 1 つの倍率では、3 ビットで正解率が下がり始めました。塊ごとなら保てています。2 ビットのときと同じ傾向です

## 2 塊の大きさを変える

```python
from roadmap_examples.evalset import load_cases
from roadmap_examples.p07_classify import DEFAULT_EVAL
from roadmap_examples.p09_lora import BASE_TRAIN, SFT_TRAIN, merge, run_all
from roadmap_examples.p09_quant import mean_abs_error, quantize

run = run_all(load_cases(BASE_TRAIN), load_cases(SFT_TRAIN), load_cases(DEFAULT_EVAL))
w1 = merge(run.base, run.lora).w1
for group in (8, 32, 128, None):
    print(group, quantize(w1, 4, group).n_bytes, round(mean_abs_error(w1, 4, group), 4))
```

| 塊の大きさ | w1 の大きさ（バイト） | 平均のずれ |
|---|---|---|
| 8 | 12,288 | 0.0221 |
| 32 | 9,216 | 0.0331 |
| 128 | 8,448 | 0.0412 |
| 全体で 1 つ | 8,194 | 0.0600 |

塊の大きさの決め方:

- 塊を小さくするほど、ずれは小さくなりますが、倍率の数が増えて大きくなります。塊 8 では、倍率の分（4,096 バイト）が整数の分（8,192 バイト）の半分にもなります
- 32 は、大きさの増え方（全体で 1 つより約 12% 増し）に対して、ずれがほぼ半分（0.060 → 0.033）になっています。この表では 32 あたりがつり合いの良い所です
- 塊の大きさは、行列の要素の数を割り切れる値にします（`w2` は 160 個なので、128 では割り切れません）

## 3 架空の 1B のモデルの見積もり

```bash
uv run python -m roadmap_examples.p09_quant --params 1 --layers 16 --hidden 2048 --rank 8
```

```text
LoRA で学習する重み: 2,097,152 個（全体の 0.21%）
| フルの調整 | 18.0 |
| LoRA | 2.0 |
| QLoRA | 0.5 |
```

KV キャッシュは `kv_cache_gb(16, 8, 128, 4096)` で約 0.27 GB です。

| 用途 | 見積もり |
|---|---|
| 推論（4 ビット） | 重み 0.5 GB + KV キャッシュ 0.27 GB + 実行の分 → 1〜2 GB ほど見ておく |
| 推論（16 ビット） | 重み 2.0 GB + KV キャッシュ 0.27 GB + 実行の分 → 3 GB ほど |
| LoRA の学習 | 2.0 GB + 活性化（入力の長さとバッチで変わる） |
| フルの調整 | 18 GB + 活性化 |

判断の例（メモリ 16 GB・GPU なしの PC の場合）:

- 推論と LoRA の学習は、ふつうのメモリで動く見込みがあります（GPU が無いので遅い）。入力を短く、バッチを小さくして始めます
- フルの調整は、活性化を足すとメモリに収まらない恐れが大きいので、LoRA にします
- 見積もりは目安です。まず学習の例 10 件・1 エポックで動かし、実際に使ったメモリを見てから設定を広げます
