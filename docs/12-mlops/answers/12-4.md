## 1 エラーの割合のしきい値

`p12_monitor.py` の `Thresholds` に `max_error_rate` を足し、`alerts` に 1 つ確かめを足します。ここでは、元のコードを直さずに確かめられる形で書きます。

```python
from dataclasses import dataclass

from roadmap_examples.p12_monitor import Stats, Thresholds, alerts, stats


@dataclass(frozen=True)
class MoreThresholds(Thresholds):
    max_error_rate: float | None = None  # モデルに繋がらなかった割合


def more_alerts(s: Stats, t: MoreThresholds) -> list[str]:
    found = alerts(s, t)
    if t.max_error_rate is not None and s.rate("error") > t.max_error_rate:
        found.append(f"エラーの割合が {s.rate('error'):.0%} です（しきい値 {t.max_error_rate:.0%}）")
    return found


def record(status: str) -> dict:
    return {"status": status, "latency_ms": 100.0, "input_tokens": 10, "output_tokens": 1, "cost": 0.0}


def test_error_rate_threshold() -> None:
    s = stats([record("answered"), record("error")])
    assert more_alerts(s, MoreThresholds(max_error_rate=0)) == ["エラーの割合が 50% です（しきい値 0%）"]
    assert more_alerts(s, MoreThresholds(max_error_rate=0.5)) == []
    assert more_alerts(stats([record("answered")]), MoreThresholds(max_error_rate=0)) == []
```

コマンドで使うには、`parse_args` に `--max-error-rate` を足し、`main` で `Thresholds` に渡します。

なぜこうするか:

- エラー（`503`）は、モデルに繋がらないときに出ます。応答時間や止めた割合とは別の原因なので、別のしきい値で見ます
- しきい値ちょうど（50% で しきい値 50%）は知らせない、という境目もテストで決めています

## 2 往復の回数を数える

```python
from pathlib import Path

from roadmap_examples.p12_monitor import load_records


def model_rounds(record: dict) -> int:
    return sum(1 for span in record.get("trace", []) if span["kind"] == "model")


records = load_records(Path("data/p12/requests-sample.jsonl"))
rounds = [model_rounds(r) for r in records]
print(sum(rounds) / len(rounds), max(rounds))
print([r["status"] for r in records if model_rounds(r) == max(rounds)])
```

```text
2.3 6
['stopped', 'stopped']
```

読み方:

- 平均 2.3 回（入力で止めた 2 件は 0 回として数えています）。検索 → 答え（2 回）か、言い換えて検索 1 回を足した 3 回がふつうです
- 最大の 6 回の 2 件は、どちらも `stopped`（往復の上限 6 回で止まった）でした。上限まで往復した依頼が、そのまま止まっています。
  `trace` の各往復の `tool_calls` を見て、同じ検索を繰り返していないかを確かめます

## 3 プロンプトの版のテスト

```python
from roadmap_examples.p08_chunk import load_chunks
from roadmap_examples.p08_rag import DEFAULT_DOCS
from roadmap_examples.p08_search import BM25
from roadmap_examples.p10_agent import MemoryIssueTracker, qa_tools
from roadmap_examples.p11_guard import GuardConfig
from roadmap_examples.p12_api import prompt_version


def test_prompt_version_changes_with_contents_and_order() -> None:
    tools = qa_tools(BM25(load_chunks(DEFAULT_DOCS)), MemoryIssueTracker())
    base = prompt_version(tools, GuardConfig())
    assert prompt_version(tools, GuardConfig()) == base  # 同じ中身なら同じ版
    assert prompt_version(tools, GuardConfig(canary="CANARY-other")) != base  # system が 1 文字でも違えば別の版
    assert prompt_version(list(reversed(tools)), GuardConfig()) != base  # ツールの並び順でも変わる
```

並び順で版が変わるのは、**良いこと** と考えます。

- モデルに渡すツールの一覧の順番が変わると、モデルの選び方が変わることがあります。モデルにとっては別のプロンプトです
- 版が変わって困るのは「意味の無い並べ替えで、比べる相手が変わる」ときです。並び順は、コードの中で決まった順（`qa_tools` の順）にそろえておけば、勝手には変わりません
