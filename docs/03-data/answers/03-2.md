## 1 分類ごとの件数（SQL と pandas）

```python
import pandas as pd

from roadmap_examples.p03_pipeline import DATA, read_clean
from roadmap_examples.p03_sql import connect, query

CATEGORY_COUNTS = "SELECT category, COUNT(*) AS n FROM inquiries GROUP BY category ORDER BY category"


def test_category_counts_sql_equals_pandas() -> None:
    clean = read_clean(DATA / "inquiries_clean.csv")
    conn = connect({"inquiries": clean})
    sql = query(conn, CATEGORY_COUNTS)
    pdf = clean.groupby("category").size().reset_index(name="n").sort_values("category", ignore_index=True)
    pd.testing.assert_frame_equal(sql, pdf, check_dtype=False)
```

どの分類も 26 件ずつです。並べる順（`ORDER BY` と `sort_values`）をそろえないと、中身が同じでも表としては違うと判断されます。
`check_dtype=False` は、整数の型の違い（SQLite の整数と、pandas の整数の種類）を無視するためです。

## 2 問い合わせが 5 件以上の顧客

```sql
SELECT customer_id, COUNT(*) AS n
FROM inquiries
GROUP BY customer_id
HAVING COUNT(*) >= 5
ORDER BY n DESC, customer_id
```

| customer_id | n |
|---|---|
| K-0014 | 7 |
| K-0030 | 7 |
| K-0011 | 6 |
| K-0027 | 6 |
| K-0005・K-0010・K-0013・K-0029・K-0031 | 5 |

件数で絞るのは集計の後なので、WHERE ではなく HAVING です。同じ件数の顧客は ID の順に並べ、結果を毎回同じにしています。

## 3 内部結合で消える問い合わせ

```python
from roadmap_examples.p03_pipeline import (
    CUSTOMER_COLUMNS,
    DEFAULT_CUSTOMERS,
    DEFAULT_RAW,
    RAW_COLUMNS,
    read_csv_as_text,
)


def test_dropped_by_inner_join() -> None:
    raw = read_csv_as_text(DEFAULT_RAW, RAW_COLUMNS)
    customers = read_csv_as_text(DEFAULT_CUSTOMERS, CUSTOMER_COLUMNS)
    conn = connect({"inquiries": raw, "customers": customers})
    lost = query(
        conn,
        """
        SELECT i.id, i.customer_id
        FROM inquiries AS i LEFT JOIN customers AS c ON i.customer_id = c.customer_id
        WHERE c.customer_id IS NULL
        ORDER BY i.id
        """,
    )
    formatted = lost["customer_id"].str.upper().str.replace(r"^K-?", "K-", regex=True)
    in_master = formatted.isin(customers["customer_id"])
    assert (int(in_master.sum()), int((~in_master).sum())) == (19, 2)
```

左外部結合で、相手がいなかった行（右の列が NULL）だけを残すと、内部結合で消える行の一覧になります。

| 理由 | 件数 | 例 |
|---|---|---|
| 顧客 ID の書き方が違う（書き方をそろえれば一覧にある） | 19 | `K0019`・`k-0021` |
| 顧客の一覧に無い | 2 | `K-0099`・`K-0098` |

前の 19 件は、書き方をそろえれば結合できます（03-3 の `normalize_customer_id`）。
後の 2 件は、そろえても相手がいないので、プランを unknown（不明）として残すか、捨てるかを決めます。
03 のパイプラインでは、分類の学習には本文が使えるので残し、件数を報告しています。
