## 1 JSONL を 07 の load_cases で読む

```python
import io
from collections import Counter
from pathlib import Path

from roadmap_examples.evalset import load_cases
from roadmap_examples.p03_pipeline import main


def test_cases_jsonl_loads_with_07_loader(tmp_path: Path) -> None:
    out, cases_path = tmp_path / "clean.csv", tmp_path / "train.jsonl"
    assert main(["--out", str(out), "--cases", str(cases_path)], stdout=io.StringIO()) == 0
    cases = load_cases(cases_path)  # 形式の誤りや id の重複があれば、ここで止まる
    assert len(cases) == 130
    assert Counter(c.expected["category"] for c in cases) == dict.fromkeys(
        ["billing", "account", "bug", "contract", "other"], 26
    )
```

07 の評価セットと同じ読み込み関数で読めるので、04 では、学習用のデータ（03 の出力）と評価用のデータ（07 の評価セット）を同じ形で扱えます。

## 2 is_question を足す

`examples/src/roadmap_examples/p03_features.py` を直します。

```python
NUMERIC = ["input_length", "hour", "is_question"]


def add_features(df: pd.DataFrame) -> pd.DataFrame:
    return df.assign(
        input_length=df[TEXT].str.len(),
        hour=df["received_at"].dt.hour,
        is_question=df[TEXT].str.endswith("か。").astype(int),  # 「〜ですか。」「〜ますか。」なら 1
    )
```

```python
def test_is_question_feature(data) -> None:
    train, _ = split(data)
    names = build_preprocessor().fit(train).get_feature_names_out()
    assert "num__is_question" in names
    assert data.loc[data["id"] == "Q0006", "is_question"].item() == 0  # 「お礼を伝えてください。」
```

なぜこうするか:

- 行ごとに決まる計算なので、`add_features` に書きます（学習用のデータから学ぶ値は使っていない）
- 列の名前を `NUMERIC` に足すだけで、穴埋めと標準化が自動でかかります。前処理の組み立て（`build_preprocessor`）は直さずに済みます
- 既存のテスト `test_leaky_columns_are_not_used` の、使う列の一覧にも `is_question` を足します。使う列が増えたことを、テストの差分でレビューできます

130 件中 39 件が質問の形で、分類ごとの割合は contract 58%・billing 38%・other 35%・account 19%・bug 0% でした。
不具合の連絡は「〜します」「〜されます」で終わることが多く、質問の形にならないからです。分類の手がかりになりそうです（効くかどうかは 04 で測ります）。

## 3 全体で fit した語彙と、学習用だけの語彙

```python
from roadmap_examples.p03_features import add_features, build_preprocessor, split
from roadmap_examples.p03_pipeline import DATA, read_clean

df = add_features(read_clean(DATA / "inquiries_clean.csv"))
train, test = split(df)
vocab_all = build_preprocessor(text_only=True).fit(df).named_transformers_["text"].vocabulary_
vocab_train = build_preprocessor(text_only=True).fit(train).named_transformers_["text"].vocabulary_
print(len(vocab_all), len(vocab_train), len(set(vocab_all) - set(vocab_train)))  # 1519 1271 248
```

全体で fit すると、評価用の 33 件にしか出てこない 248 個の並びが語彙に入ります。
これらは、学習用のデータだけで作ったモデルなら「知らない並び」として無視されるはずのものです。
全体で fit すると、評価用のデータの文に合わせた列が用意され、評価用のデータが実際より「見慣れた」ものになります。

ただし、モデルの重みは学習用のデータだけで学ぶので、この 248 列の重みはほぼ 0 です。語彙のリークの影響は小さいこともあります。
影響が大きいのは、中央値・平均・標準偏差のように、全体の値が評価用のデータの変換に直接使われる場合です。
どちらにしても、「先に分けて、学習用だけで fit」を習慣にしておけば、影響の大小を考えずに済みます。
