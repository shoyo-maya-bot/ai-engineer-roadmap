## 1 「ｅメール」を email にする

```pycon
>>> import pandas as pd
>>> from roadmap_examples.p03_pipeline import CHANNEL_ALIASES, map_aliases, normalize_key
>>> normalize_key("ｅメール")
'eメール'
>>> map_aliases(pd.Series(["ｅメール"]), CHANNEL_ALIASES).tolist()
[nan]
```

NFKC で全角の「ｅ」は半角の「e」になりますが、「eメール」は対応表に無いので欠損になり、窓口は unknown になります。
対応表に 1 行足します。キーは `normalize_key` を通した後の形（半角・小文字）で書きます。

```python
CHANNEL_ALIASES = {
    # （中略）
    "e-mail": "email",
    "eメール": "email",
    # （中略）
}
```

```python
def test_e_mail_in_japanese_maps_to_email() -> None:
    s = pd.Series(["ｅメール", "Eメール", "eメール"])
    assert map_aliases(s, CHANNEL_ALIASES).tolist() == ["email"] * 3
```

全角・大文字・半角の 3 通りを 1 行のキーで受けられるのは、`normalize_key` で先にそろえているからです。
対応表を足すたびに、「どの書き方が来るか」をテストに残しておくと、後で対応表を整理したときに壊していないかを確かめられます。

## 3 本文が 5 文字未満の行を捨てる

`clean_inquiries` の `rules` に、理由を 1 つ足します。捨てる行の判断は、ほかの理由と重ならないように書きます。

```python
MIN_INPUT_LENGTH = 5  # これより短い本文は、分類の材料にならない

rules = {
    "本文が空": df["input"].isna(),
    "本文が短すぎる": df["input"].str.len() < MIN_INPUT_LENGTH,
    "分類が空": df["input"].notna() & blank_category,
    "分類が 5 種類のどれでもない": df["input"].notna() & ~blank_category & df["category"].isna(),
}
report.dropped = {reason: int(mask.sum()) for reason, mask in rules.items()}
keep = ~pd.concat(rules, axis=1).any(axis=1)  # どれか 1 つでも当てはまれば捨てる
```

```python
def test_short_input_is_dropped(tmp_path: Path) -> None:
    raw = tmp_path / "raw.csv"
    raw.write_text(
        "受付番号,受付日時,顧客ID,窓口,本文,分類,対応時間（分）\n"
        "Q1,2026-04-01 10:00,K-0001,メール,至急,other,5\n"
        "Q2,2026-04-01 11:00,K-0001,メール,請求書を再発行してください。,billing,5\n",
        encoding="utf-8",
    )
    df, report = run(raw, DATA / "customers.csv")
    assert df["id"].tolist() == ["Q2"]
    assert report.dropped["本文が短すぎる"] == 1
```

なぜこうするか:

- 欠損の本文では `str.len()` が欠損になり、`< 5` は False になります。「本文が空」と「短すぎる」が二重に数えられません
- `keep` を、理由を並べた表の「どれかが True」から作ると、理由を足すたびに `keep` の式を書き換えずに済みます
- 元のデータの本文は最短でも 12 文字なので、サンプルのデータでは捨てる件数は 0 です。テスト用の小さな CSV で、捨てる場合を確かめます
- この決まりを足しても、`test_run_on_sample_data_reports_every_drop` の `report.dropped` の期待値に「本文が短すぎる: 0」を足す必要があります。
  件数を固定したテストが、決まりの追加を知らせてくれます
