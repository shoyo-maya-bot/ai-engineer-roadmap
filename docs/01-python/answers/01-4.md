# 01-4 解答

[01-4 クラス設計・pytest・ruff](../01-4-class-pytest-ruff.md) の演習の解答の一例です。

## 1 先にテストを書く

`examples/tests/test_p01_api_to_csv.py` の `FakeGetter` と `run` を使います。

```python
ITEMS5 = [{"id": i} for i in range(1, 6)]


@pytest.mark.parametrize(("limit", "want"), [("2", ["id", "1", "2"]), ("10", ["id", "1", "2", "3", "4", "5"])])
def test_limit(limit: str, want: list[str]) -> None:
    code, out = run(["--url", "https://api.example.com/x", "--fields", "id", "--limit", limit], FakeGetter(ITEMS5))
    assert code == 0
    assert out.splitlines() == want


@pytest.mark.parametrize("limit", ["0", "-1"])
def test_limit_must_be_positive(limit: str) -> None:
    with pytest.raises(SystemExit) as e:
        run(["--url", "https://api.example.com/x", "--fields", "id", "--limit", limit], FakeGetter(ITEMS5))
    assert e.value.code == 2  # 引数の誤り
```

直す前に流すと、`--limit` を知らない argparse が終了コード 2 で止まり、`test_limit` が失敗します。
「失敗するテスト」を先に見ておくと、テストが本当に新しい動きを確かめていることが分かります。

## 2 parse_args と main を直す

```python
# parse_args の中（--timeout の後）
parser.add_argument("--limit", type=int, help="先頭の N 件だけを CSV にする（1 以上）")
args = parser.parse_args(argv)
if args.limit is not None and args.limit < 1:
    parser.error("--limit は 1 以上にしてください")

# main の中
rows = to_rows(items[: args.limit], args.fields)  # limit が None なら全件
```

なぜこうするか:

- `parser.error` は、使い方を表示して終了コード 2 で終わります。既存の `--fields` の誤りと同じ扱いにそろえました
- `items[:None]` は全件を返します。`if args.limit:` の分岐を書かずに済みます
- 件数の上限は、取ってきた後で切っています。API に「件数の上限」の引数があるなら、そちらで絞るほうが通信も減ります

## 3 lint とコミット

```bash
uv run pytest
uv run ruff check .. && uv run ruff format --check ..
git switch -c add-limit
git add src/roadmap_examples/p01_api_to_csv.py tests/test_p01_api_to_csv.py
git commit -m "api-to-csv に --limit（先頭の N 件だけ）を足す"
git log --oneline -1
```

`ruff format --check` で失敗したら、`uv run ruff format ..` で直してから、もう一度確かめます。

テストが通り、0 以下を引数の誤りにできていれば、別の書き方（`type=` に自作の関数を渡して検査する、など）でも構いません。
