# 01-2 解答

[01-2 Linux の基本操作と HTTP API の呼び方](../01-2-linux-http.md) の演習の解答の一例です。

## 1 シェルで CSV を調べる

```bash
cd <作業フォルダ>/examples
grep 99999 data/p03/inquiries_raw.csv | cut -d, -f1      # Q0018・Q0059・Q0104
cut -d, -f4 data/p03/inquiries_raw.csv | sort | uniq -c   # 窓口の値の種類と数
```

窓口の値は 14 種類（と列名の「窓口」）に分かれます。「メール」「mail」「E-mail」「ﾒｰﾙ」は同じ意味なのに、別の値として数えられます。
これが「表記ゆれ」で、03-3 で直します。

空の値が 14 件と数えられますが、本当に窓口が空の件は 10 件です。残りは、本文の途中で改行した件の 2 行目です。

```bash
grep -n '"' data/p03/inquiries_raw.csv | head -4
```

引用符で始まる本文が、次の行に続いています。`cut` は 1 行ずつ処理するので、2 行目を別の件として扱ってしまいます。
シェルの道具は「ざっと見る」には便利ですが、正しく数えるには CSV を読める道具を使います。

## 2 手元のサーバーで api-to-csv を動かす

```bash
# シェル 1
mkdir -p /tmp/api && cd /tmp/api
echo '{"data": {"items": [{"id": 1, "name": "会員 A", "owner": {"name": "部署 A"}}, {"id": 2, "name": "会員 B", "owner": null}]}}' > items.json
python -m http.server 8000

# シェル 2（examples/ で）
uv run api-to-csv --url http://localhost:8000/items.json --items-key data.items --fields id,name,owner.name
# id,name,owner.name
# 1,会員 A,部署 A
# 2,会員 B,
uv run api-to-csv --url http://localhost:8000/nothing.json --fields id -o out.csv; echo $?
# エラー: HTTP Error 404: File not found
# 1
ls out.csv   # 無い
```

`owner` が `null` の件は、`owner.name` を空欄にします（`pick` が `None` を返し、`to_cell` が空の文字列にする）。
エラーのときは、CSV のファイルを開く前に `return 1` しているので、中途半端なファイルが残りません。

## 3 やり直すか

| コード | やり直すか | 理由 |
|---|---|---|
| 400 | やり直さない | 要求の形が誤っている。同じ要求は何度送っても失敗する |
| 401 | やり直さない | 認証が通っていない。キーを直すまで成功しない |
| 429 | 待ってからやり直す | 送りすぎ。`Retry-After` があればその秒数待つ。回数の上限も決める |
| 503 | 待ってからやり直す | サーバーが一時的に使えない。間隔を少しずつ空け、回数の上限を決める |

やり直す場合も、回数と待つ時間の上限を必ず決めます。上限が無いと、相手が直らない限り止まりません。
