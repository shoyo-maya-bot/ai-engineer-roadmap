## 1・2 二重のループの版と、set の版

```python
import pytest


def slow_new_customers(today: list[str], known: list[str]) -> list[str]:
    out: list[str] = []
    for c in today:
        if c not in known and c not in out:  # どちらも list の in（O(n)）
            out.append(c)
    return out


def new_customers(today: list[str], known: list[str]) -> list[str]:
    known_set = set(known)  # 1 回だけ作る（O(len(known))）
    seen: set[str] = set()
    out: list[str] = []
    for c in today:
        if c not in known_set and c not in seen:  # どちらも set の in（平均 O(1)）
            seen.add(c)
            out.append(c)
    return out


@pytest.mark.parametrize("func", [slow_new_customers, new_customers])
def test_new_customers(func) -> None:
    assert func(["K-3", "K-1", "K-3", "K-2"], ["K-1"]) == ["K-3", "K-2"]  # 出てきた順・重複なし
    assert func([], ["K-1"]) == []
    assert func(["K-1"], []) == ["K-1"]
```

なぜこうするか:

- `pytest.mark.parametrize` で、同じテストを 2 つの版に流します。直した版が、元の版と同じ結果を返すことを確かめられます
- `set(today) - set(known)` と書くと 1 行ですが、set には順番が無いので「出てきた順」が崩れます。順番が要るときは、上のように list と set を併せて使います

## 3 測った結果

`random.Random(0)` で、0〜2n の番号の顧客 ID を、`today` と `known` に n 件ずつ作りました。

| 件数 n | 二重のループの版 | set の版 |
|---|---|---|
| 1,000 | 約 16 ミリ秒 | 約 0.1 ミリ秒 |
| 10,000 | 約 1,700 ミリ秒 | 約 1.4 ミリ秒 |

測った条件: 手元の Linux（2 コアの仮想マシン）・演習の環境（`uv run`）・`measure(..., repeat=3)` の最も速い値。

件数が 10 倍で、二重のループの版は約 100 倍、set の版は約 13 倍でした。
二重のループの版は、`known` と `out` の 2 つの list を毎回見るので、`dedupe` の例より遅くなっています。

数字は環境で変わります。大事なのは、件数を変えたときの増え方（約 100 倍か、約 10 倍か）を比べることです。
