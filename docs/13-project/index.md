# 13 実践プロジェクト

!!! abstract "到達目標"
    - 要件から配備までを 1 人で通し、設計書と評価結果つきでレビューを受けられる

## 前提

- 前提の部: [11 AI の安全と評価](../11-safety/index.md)・[12 MLOps とデプロイ](../12-mlops/index.md)
- 01〜12 の成果物（とくに 07 の評価セット、10 のエージェント、11 の攻撃例、12 の配備手順）を使います
- LLM はローカルのモデル（Ollama）で進めます。クラウドの API で動かすのは任意で、費用の見積もり（13-2）は両方について書きます

## 課題

次のどれか 1 つを選び、要件から配備までを 1 人で通します。どれも架空の業務を題材にします。
課題ごとの要件（必須と任意）は [13-1](13-1-requirements-design.md) にあります。

| 課題 | 内容 | 状態 |
|---|---|---|
| チャットボット | 社内の手続きの質問に答える | 公開（[13-1](13-1-requirements-design.md)） |
| 設計書 Q&A（RAG） | 架空の設計書に出典つきで答える | 公開（[13-1](13-1-requirements-design.md)） |
| レビュー支援エージェント | 変更の差分を読み、確認観点を挙げる（人が承認する） | 公開（[13-1](13-1-requirements-design.md)） |

## 章の一覧

どの章も「何か → なぜ必要か → どうやるか → 演習 → もし〇〇がなかったら？ → 理解度チェック」の順に並びます。演習は課題を進める手順で、解答は課題 B を選んだ場合の例です。

| 章 | 内容 | 状態 |
|---|---|---|
| [13-1 要件と設計書](13-1-requirements-design.md) | 課題を選び、要件・やらないこと・判断の理由を書く | 公開 |
| [13-2 評価セットと費用の見積もり](13-2-evaluation-cost.md) | 評価セットと攻撃例を流し、月の費用を見積もる | 公開 |
| [13-3 配備・レビュー・振り返り](13-3-deploy-review.md) | 配備と監視・提出前の確かめ・レビュー・振り返り | 公開 |

## 提出物

- 設計書（要件・構成・RAG か学習かの判断・人の承認を置く場所）
- 評価セットと結果
- 費用の見積もり（ローカルのモデルで動かす場合と、クラウドの API を使う場合）
- 配備の手順
- 振り返り（うまくいったこと・次に直すこと）

ひな形と確かめの道具（`examples/src/roadmap_examples/p13_project.py`）:

- `uv run python -m roadmap_examples.p13_project init my-project`（`design.md`・`cost.md`・`deploy.md`・`retro.md` と `eval/` を作る）
- `uv run python -m roadmap_examples.p13_project estimate <評価の結果>.jsonl --per-day <1 日の件数>`（月の費用の見積もり）
- `uv run python -m roadmap_examples.p13_project check my-project`（提出物がそろっているか）
