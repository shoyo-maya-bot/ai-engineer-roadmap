# 02-3 確率・分布・検定の考え方

!!! abstract "到達目標"
    - 小さな評価セットで測った正解率が、どれくらいばらつくかを、シミュレーションで示せる
    - ブートストラップで、正解率の信頼区間を求めて説明できる
    - 2 つの方法の正解率の差が、偶然でも出る差かどうかを、並べ替え検定で判断し、p 値の意味と限界を説明できる

## 何か

評価セットで測った正解率は、「本当の正解率」そのものではありません。たまたま選んだ件での成績です。
別の 30 件を選び直せば、同じ分類でも違う数字が出ます。この **ばらつき** を数で扱うのが、確率と統計です。

この章では、式（分布の公式）の代わりに、乱数で何千回もやり直す **シミュレーション** で確かめます。

| 考え方 | 問い | この章の方法 |
|---|---|---|
| 分布 | 本当の正解率が 70% なら、30 件で測るとどんな数字が出るか | 乱数で 1 万回測り直す |
| 信頼区間 | 測った正解率から、本当の正解率はどの範囲にありそうか | ブートストラップ（件を選び直す） |
| 検定 | 2 つの方法の差は、偶然でも出る差か | 並べ替え検定（a と b を入れ替える） |

## なぜ必要か

07 では、仮のルールベース分類（30 件中 20 件、66.7%）と LLM を、同じ評価セットで比べます。
LLM が 24 件（80.0%）正解したら、「LLM のほうが良い」と言えるでしょうか。

30 件のように小さな評価セットでは、数件の違いは偶然でも出ます。
偶然の差で「良くなった」と判断すると、効いていない変更を採用したり、本番で期待した精度が出なかったりします。
逆に、「この件数では、何ポイント以上の差でないと見分けられない」と分かれば、評価セットを何件に増やすべきかを決められます。

## どうやるか

### 測った正解率のばらつきを見る

本当の正解率が p の分類を、n 件で測ることを、乱数で何度も繰り返します。
1 件ごとに「確率 p で正解」とすると、n 件中の正解の数は二項分布に従います。

<!-- src: examples/src/roadmap_examples/p02_stats.py -->
```python title="examples/src/roadmap_examples/p02_stats.py"
def simulate_accuracy(p: float, n: int, trials: int, seed: int = 0) -> np.ndarray:
    """本当の正解率が p の分類を、n 件の評価セットで trials 回測ったときの、正解率の一覧（ばらつきを見る）."""
    rng = np.random.default_rng(seed)
    return rng.binomial(n, p, size=trials) / n
```

乱数は `np.random.default_rng(seed)` で作ります（[公式ドキュメント: Random Generator](https://numpy.org/doc/stable/reference/random/generator.html)）。
seed を決めると、毎回同じ乱数になり、結果を再現できます。

本当の正解率を 70% として、1 万回測り直した結果の、真ん中の 95% の範囲です。

| 件数 n | 測った正解率の範囲（95%） | 範囲の幅 |
|---|---|---|
| 30 | 53.3%〜86.7% | 約 33 ポイント |
| 100 | 61%〜79% | 約 18 ポイント |
| 300 | 64.7%〜75% | 約 10 ポイント |
| 1,000 | 67.2%〜72.8% | 約 6 ポイント |

30 件では、本当は 70% の分類が、60% 以下や 80% 以上と測られることが 3 割ほどあります（テストで確かめています）。
件数を 10 倍にすると、幅はおよそ 1/√10（約 3 分の 1）になります。

### 信頼区間をブートストラップで求める

実際には「本当の正解率」は分かりません。手元にあるのは、30 件の採点結果（1 か 0）だけです。
そこで、30 件から **重複を許して** 30 件を選び直し、平均を取る、を何千回も繰り返します。これをブートストラップと呼びます。

<!-- src: examples/src/roadmap_examples/p02_stats.py -->
```python title="examples/src/roadmap_examples/p02_stats.py"
def bootstrap_ci(scores: ArrayLike, resamples: int = 10_000, level: float = 0.95, seed: int = 0) -> tuple[float, float]:
    """平均の信頼区間（ブートストラップ）. 件を重複ありで選び直して平均を取る、を繰り返し、その分布の両端を返す."""
    scores = np.asarray(scores, dtype=np.float64)
    rng = np.random.default_rng(seed)
    idx = rng.integers(0, len(scores), size=(resamples, len(scores)))
    means = scores[idx].mean(axis=1)
    tail = (1 - level) / 2
    low, high = np.quantile(means, [tail, 1 - tail])
    return float(low), float(high)
```

`scores[idx]` は、番号の行列 `idx` で、1 万通りの選び直しを一度に作っています（02-1 の配列の演算）。

```pycon
>>> import numpy as np
>>> from roadmap_examples.p02_stats import bootstrap_ci
>>> bootstrap_ci(np.array([1] * 20 + [0] * 10))  # 30 件中 20 件が正解
(0.5, 0.8333333333333334)
```

仮のルールベース分類の正解率 66.7% は、「50%〜83% くらいのどこか」としか言えません。
報告するときは、正解率と一緒に、件数か信頼区間を書きます。

### 2 つの方法の差を、並べ替え検定で調べる

同じ 30 件を、方法 a と b で採点した結果があります。b のほうが 4 件多く正解しました。
この差が偶然でも出るかを、次の考え方で調べます。

1. 「a と b に本当の差は無い」と仮定する（帰無仮説）
2. 差が無いなら、件ごとに a と b の結果を入れ替えても、差の出方は変わらないはず
3. ランダムに入れ替えて差を求める、を 1 万回繰り返し、実際の差以上の差が出た割合を数える。これが **p 値**

<!-- src: examples/src/roadmap_examples/p02_stats.py -->
```python title="examples/src/roadmap_examples/p02_stats.py"
def paired_permutation_test(a: ArrayLike, b: ArrayLike, resamples: int = 10_000, seed: int = 0) -> float:
    """同じ件を 2 つの方法で採点した点 a・b の、平均の差の p 値（両側）.

    「a と b に差は無い」なら、件ごとに a と b を入れ替えても差の分布は変わらないはず.
    入れ替え（差の符号の反転）をランダムに繰り返し、実際の差以上に偏る割合を数える.
    """
    diff = np.asarray(a, dtype=np.float64) - np.asarray(b, dtype=np.float64)
    observed = abs(diff.mean())
    rng = np.random.default_rng(seed)
    signs = rng.choice([-1.0, 1.0], size=(resamples, len(diff)))
    null = np.abs((signs * diff).mean(axis=1))
    # 実際の並びも 1 回分として数える（p 値が 0 にならないように）
    return float((np.sum(null >= observed - 1e-12) + 1) / (resamples + 1))
```

同じ件を両方で採点しているので、件ごとの組（対応）を保ったまま入れ替えます。
件ごとの難しさの違いが差に混ざらないので、別々の件で比べるより、少ない件数で差を見分けられます。

30 件中 a が 20 件・b が 24 件正解で、違うのは 4 件だけ（4 件とも b が正解）の場合、p 値は約 0.12 でした。
SciPy の `scipy.stats.permutation_test`（[公式ドキュメント](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.permutation_test.html)）と同じ結果になることを、テストで確かめています。

<!-- src: examples/tests/test_p02_stats.py -->
```python title="examples/tests/test_p02_stats.py"
def test_paired_test_matches_scipy() -> None:
    a = np.array([1] * 20 + [0] * 10)
    b = np.array([1] * 24 + [0] * 6)
    want = stats.permutation_test(
        (a, b),
        lambda x, y, axis: np.mean(x - y, axis=axis),
        permutation_type="samples",  # 対応のある 2 群（件ごとに a と b を入れ替える）
        vectorized=True,
        n_resamples=10_000,
        random_state=0,
    ).pvalue
    assert paired_permutation_test(a, b, seed=0) == pytest.approx(want, abs=0.02)
    assert want == pytest.approx(0.125, abs=0.02)  # 違う 4 件がすべて b の勝ち: 2 × (1/2)^4 = 0.125
```

差の無い 2 つの方法でも、8 回に 1 回くらいは、この程度の差が出るということです。「b のほうが良い」とは、まだ言えません。

### p 値の読み方

よく使われる目安は「p 値が 0.05 より小さければ、偶然とは考えにくい」です。ただし、次の点に注意します。

!!! failure "悪い例"
    - 「p = 0.12 だから、a と b に差は無い」と結論する（差が無いことの証明ではない。件数が足りないだけかもしれない）
    - 「p = 0.001 だから、大きく良くなった」と言う（p 値は差の大きさではない。件数が多ければ小さな差でも p 値は小さくなる）
    - プロンプトを 20 通り試し、いちばん良かったものの p 値だけを報告する

!!! success "良い例"
    差の大きさ（何ポイント上がったか）と、信頼区間か p 値と、件数を一緒に書く。比べ方（何通り試したか）も書く。

20 通り試して最も良いものを選ぶと、どれも本当は同じ 70% でも、選んだものは平均で 85% 近くに見えます（演習 3）。
選んだ後は、選ぶのに使っていない別の評価セットで測り直します。

## 演習

1. 本当の正解率が 70% の分類を測るとき、95% の範囲の幅を 10 ポイント以下にするには、評価セットが何件ほど要るかを、`simulate_accuracy` で調べてください
2. 30 件の評価セットで、a は 22 件、b は 27 件正解し、a が正解した件はすべて b も正解でした。`paired_permutation_test` で p 値を求め、「b のほうが良い」と言えるかを書いてください
3. 本当の正解率がどれも 70% のプロンプトを 20 通り、30 件で測り、最も良いものを選ぶ、を 1 万回繰り返してください。選んだものの正解率の平均はいくつになりますか

- できたことの確かめ方: 1〜3 の数字と、それぞれ 1〜2 文の考察
- 目安の時間: 3 時間

## もし〇〇がなかったら？

**ばらつきを考えなかったら**、30 件で 3 ポイント上がっただけの変更を「改善」として採用し、
次の週に別の変更で 3 ポイント下がると「悪化」として戻す、を繰り返します。どちらも偶然の範囲で、実は何も変わっていません。

**選んだ評価セットで、そのまま成績を報告していたら**、何通りも試して最も良かったものを選んだ分だけ、数字が良く見えます。
本番で測ると下がり、「評価では良かったのに」となります。

## 理解度チェック

1. 本当の正解率が 70% の分類を 30 件で測ると、どれくらいの範囲の数字が出ますか。

    ??? note "答え"
        95% の範囲で、およそ 53%〜87% です。30 件の評価セットでは、数ポイントの差は偶然でも出ます。

2. ブートストラップで、件を「重複を許して」選び直すのはなぜですか。

    ??? note "答え"
        重複を許さずに 30 件から 30 件を選ぶと、毎回同じ 30 件になり、ばらつきが分からないからです。
        重複を許すと、「別の 30 件を集めていたら」を手元のデータで真似できます。

3. 同じ件を 2 つの方法で採点したとき、件ごとの組を保ったまま入れ替えるのはなぜですか。

    ??? note "答え"
        件ごとの難しさの違いを、差に混ぜないためです。違いが出た件だけが差に効くので、少ない件数でも差を見分けやすくなります。

4. p 値が 0.12 だったとき、「2 つに差は無い」と言えますか。

    ??? note "答え"
        言えません。この件数では、偶然と見分けられなかった、というだけです。
        差があるかを確かめたいなら、評価セットの件数を増やして測り直します。
