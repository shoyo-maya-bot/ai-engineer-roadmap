## 1・2 ユークリッド距離と、コサイン類似度との関係

```python
import math
from collections.abc import Sequence

import numpy as np
import pytest

from roadmap_examples.p02_vectors import cosine, normalize_rows


def euclidean(a: Sequence[float], b: Sequence[float]) -> float:
    if len(a) != len(b):
        raise ValueError("ベクトルの長さが違います")
    return math.sqrt(sum((x - y) ** 2 for x, y in zip(a, b, strict=True)))


def test_euclidean_matches_numpy() -> None:
    a, b = [1.0, 2.0, 3.0], [4.0, 0.0, 3.0]
    assert euclidean(a, b) == pytest.approx(np.linalg.norm(np.subtract(a, b)))  # 3 と 4 の直角三角形で 5
    assert euclidean(a, a) == 0.0


def test_distance_and_cosine_on_unit_vectors() -> None:
    rng = np.random.default_rng(0)
    pairs = normalize_rows(rng.normal(size=(200, 16))).reshape(100, 2, 16)  # 長さ 1 のベクトル 100 組
    for a, b in pairs:
        assert euclidean(a, b) ** 2 == pytest.approx(2 - 2 * cosine(a, b))
```

なぜこうするか:

- 乱数は `default_rng(0)` で seed を決めます。テストが毎回同じベクトルで動くので、失敗したときに同じ状況を再現できます
- 小数の計算には丸めの誤差があるので、`==` ではなく `pytest.approx` で比べます

## 3 距離の順とコサイン類似度の順が同じになる理由

‖a − b‖² を展開すると、a·a − 2a·b + b·b です。長さが 1 なら a·a = b·b = 1、a·b = cos なので、2 − 2cos になります。

距離は「2 − 2cos」の平方根なので、cos が大きいほど距離は小さくなります。
どちらで並べても順番は変わりません。08 の検索で、ベクトルデータベースが「距離」で並べていても、
長さをそろえたエンベディングなら、コサイン類似度で並べたのと同じ結果になります。

長さをそろえていないベクトルでは、この関係は成り立ちません。距離は長さの違いも含むからです。
