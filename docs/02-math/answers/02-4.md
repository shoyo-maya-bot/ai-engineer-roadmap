## 2 ミニバッチの SGD

```python
import numpy as np
import pytest

from roadmap_examples.p02_linreg import (
    Fit,
    least_squares,
    make_data,
    mse,
    mse_gradients,
    predict,
    standardize,
    to_original_scale,
)


def sgd(X, y, lr: float, epochs: int, batch_size: int, seed: int = 0) -> Fit:
    rng = np.random.default_rng(seed)
    X, y = np.asarray(X, dtype=np.float64), np.asarray(y, dtype=np.float64)
    w, b = np.zeros(X.shape[1]), 0.0
    history = []
    for _ in range(epochs):
        order = rng.permutation(len(X))  # 1 巡ごとに、順番を混ぜる
        for start in range(0, len(X), batch_size):
            idx = order[start : start + batch_size]
            grad_w, grad_b = mse_gradients(X[idx], y[idx], w, b)  # 32 件だけで勾配を求める
            w, b = w - lr * grad_w, b - lr * grad_b
        history.append(mse(y, predict(X, w, b)))
    return Fit(w, b, history)


def test_sgd_gets_close_to_least_squares() -> None:
    X, y = make_data()
    Xs, mean, std = standardize(X)
    w, b = to_original_scale(sgd(Xs, y, lr=0.05, epochs=50, batch_size=32), mean, std)
    w_ls, b_ls = least_squares(X, y)
    assert mse(y, predict(X, w, b)) < 1.01 * mse(y, predict(X, w_ls, b_ls))  # 損失は 1% 以内
    assert np.allclose(w, w_ls, atol=0.2)  # 係数は少し揺れる
```

結果は、1 文字あたり 0.300・添付 1 つあたり 7.68・切片 5.44 で、損失は 15.73（最小二乗は 15.68）でした。

なぜこうするか:

- ミニバッチの勾配は、全件の勾配の「近似」です。1 回の計算が軽いので、データが大きいときに速く進めます
- 学習率が一定だと、最後まで少しずつ揺れ続けるので、係数は最小二乗とぴったりは一致しません。
  損失で比べると、ほぼ同じところに着いています。実際の学習では、学習率を少しずつ下げて揺れを抑えます
- 1 巡ごとに順番を混ぜるのは、毎回同じ組み合わせの 32 件で学習して、偏るのを避けるためです

## 3 外れ値の影響

```python
X, y = make_data()
y_bad = y.copy()
y_bad[:5] += 200  # 200 件中の 5 件だけ、入力の誤りで 200 分多い
print(least_squares(X, y))  # 0.297・7.54・切片 6.0
print(least_squares(X, y_bad))  # 0.243・8.12・切片 16.3
```

2.5% の件の誤りで、切片が 6 分から 16 分に、1 文字あたりの係数も 0.297 から 0.243 に変わりました。

最小二乗は MSE を最小にします。MSE は外れを 2 乗するので、200 分ずれた 5 件の分が損失の大部分を占め、
係数がその 5 件に合わせて動きます。MAE を最小にする方法（中央値に近い考え方）なら、影響はずっと小さくなります。

実務では、損失を変える前に、03-3 のように外れ値の原因（入力の誤りか、本当に時間がかかったのか）を調べて、データの側を直すのが先です。
