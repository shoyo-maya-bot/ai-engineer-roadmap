# 02-3 解答

[02-3 確率・分布・検定の考え方](../02-3-probability-testing.md) の演習の解答の一例です。

## 1 範囲の幅を 10 ポイント以下にする件数

```python
import numpy as np

from roadmap_examples.p02_stats import simulate_accuracy

for n in (300, 320, 340, 360, 400):
    acc = simulate_accuracy(0.7, n, trials=10_000)
    low, high = np.quantile(acc, [0.025, 0.975])
    print(n, round(high - low, 3))
# 300 0.103 / 320 0.1 / 340 0.097 / 360 0.094 / 400 0.09
```

およそ 320〜340 件です。30 件の約 11 倍です。
幅は件数の平方根に反比例するので、幅を 3 分の 1 にするには、件数を約 9〜10 倍にする必要があります。

全部を一度に集めなくても構いません。まず 30 件で大きな差（20 ポイント以上）を見分け、
細かな差を比べたくなった段階で、件数を増やします。

## 2 a が 22 件・b が 27 件のとき

```python
from roadmap_examples.p02_stats import paired_permutation_test

a = np.array([1] * 22 + [0] * 8)
b = np.array([1] * 27 + [0] * 3)  # a が正解した 22 件は、b もすべて正解
print(paired_permutation_test(a, b))  # 約 0.067
```

違いが出たのは 5 件で、5 件とも b が正解でした。差の無い 2 つでも、15 回に 1 回くらいは、この程度の差が出ます。
0.05 の目安では「偶然とは考えにくい」とまでは言えません。

ただし、差の大きさは 16.7 ポイントと大きく、b が悪かった件は 1 件もありません。
「b のほうが良さそうだが、30 件では確かめ切れない。件数を増やして測り直す」と書くのが妥当です。

## 3 20 通りから最も良いものを選ぶと

```python
rng = np.random.default_rng(0)
best = rng.binomial(30, 0.7, size=(10_000, 20)).max(axis=1) / 30  # 1 万回 × 20 通りの中の最高
print(best.mean(), np.quantile(best, [0.05, 0.5, 0.95]))  # 約 0.85、[0.80 0.83 0.90]
```

どのプロンプトも本当は 70% なのに、選んだものの正解率は平均で約 85% に見えます。
「最も良かったもの」を選ぶこと自体が、偶然うまくいったものを選ぶことになるからです。

対策は、選ぶのに使った評価セットとは別に、選んだ後で測るための評価セットを取っておくことです。
04 で学ぶ「学習用・検証用・評価用にデータを分ける」も、同じ理由です。
